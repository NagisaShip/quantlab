# 发布与升级（个人/GitHub Release）

> 适用：单机个人研究版（Windows 桌面）。数据默认只在本机项目 `.quantlab/` 与所选文件夹；只有用户显式配置的模型服务商、行情源、搜索源会访问网络。服务器多用户版另见部署文档。

## 版本标识

- 应用版本与构建信息：`GET /api/local/info` 返回 `version`、`build`、`desktop_version`、`started_at`、`pid`；桌面壳只复用版本/构建一致的本地后端。
- 数据库 schema：`quantlab.db` 的 `schema_migrations` 表记录已执行迁移；启动时按文件名顺序执行 `src/quant_agent/platform/migrations/*.sql` 中未执行的脚本。
- 项目格式：`.quantlab/project.json` 的 `format` 为 `quantlab.local-project/1`；升级不改变已有项目目录布局。

## GitHub Release 手动更新（当前推荐）

个人版不做静默自动更新；检查更新只打开 Release 页面，由用户确认。

1. 发布前在本机跑通：`python -m pytest` 相关测试、`web` 的 `tsc -b` / `npm run build:windows`、桌面 `cargo check`、原生启动与关闭回归。
2. 构建 Windows 安装/便携包，产物命名包含版本与平台（例如 `QuantLab-0.1.0-preview.2-windows-x64.zip`）。
3. 在 GitHub 创建 Release，上传安装包/便携包；正文写：
   - 版本号与构建号；
   - 数据库 schema 是否有新迁移；
   - 破坏性变更、需要用户手动处理的事项；
   - 已知限制（真实资金默认关闭、实验性能力等）。
4. 用户升级前：在应用内「导出项目」做一次完整备份（`.quantlab` + 项目文件），或手动复制整个项目文件夹。
5. 用户解压新版本，打开同一项目目录；后端启动时自动执行未应用的迁移。若迁移失败：
   - 不要继续写入；保留原始 `quantlab.db`；
   - 用升级前备份恢复项目；
   - 在 Release 反馈中附 `logs/` 与 `/api/local/info` 的版本信息。
6. 回滚：装回旧版本应用，恢复升级前项目备份；不要用新版本数据库直接给旧版本使用。

## 升级前检查清单

- [ ] 项目已完整备份（复制整个项目文件夹，或使用「导出项目」）。
- [ ] 磁盘空间足够（研究工件/缓存可能很大；设置 → 本地项目可清理缓存，但固定成果不会被清）。
- [ ] 记录当前版本、schema 版本、最近的运行 id。
- [ ] 若使用真实交易能力：升级前先关闭/停止所有实盘与模拟任务；升级后重新逐项确认功能开关与限额。桌面默认关闭真实资金能力，需要用户显式开启并二次确认。
- [ ] 若配置了模型/搜索密钥：确认新版本仍能读取本机加密配置；密钥不会上传到 GitHub。

## 不在本流程内

- 不提供云端账号迁移、跨设备自动同步或后台自动升级。
- 不把 `.quantlab`、`account-secrets/`、`demo-secrets/`、API key 打进 Release 包或仓库。
- 服务器多用户版的部署、角色权限与审计按服务器部署文档执行，不与个人版混用数据目录。
