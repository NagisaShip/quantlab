# 上线验证与「问 AI」平台工具

策略从回测走到模拟盘，中间要回答三个问题：模拟得准不准、扛不扛得住极端行情、跑起来是否还符合说明书。
左侧「真实结果 → 上线验证」页面把这三件事和晋级规则放在一起。**实盘下单仍然关闭**，「毕业」只是一个标签。

## 1. 毕业闸门

阶段：回测 → 纸面模拟 → 交易所模拟盘 → 毕业。每次晋级都要全部检查通过，再由人点「确认晋级」。

| 晋级到 | 检查（默认阈值，管理员可改） |
| --- | --- |
| 纸面模拟 | 有成功的回测；DSR ≥ 0.95（按「研究纪律」里的试验次数折算，没有记录时按 1 次；参数优化的每一组试验都算）；回测最大回撤 ≤ 30%；**当前这版代码做过策略体检，且没有「严重」项** |
| 交易所模拟盘 | 纸面模拟跑满 7 天；期间最大回撤 ≤ 15%；纸面 vs 回测真实度偏差 ≤ 150 bp |
| 毕业 | 交易所模拟盘跑满 14 天；最大回撤 ≤ 15%；模拟盘 vs 回测偏差 ≤ 300 bp；没有未解除的熔断 |

可以随时降级（比如改了代码）。每次晋级、降级都记在历史里，带操作人和备注。

接口：`GET /api/validation/graduation`、`GET /api/validation/graduation/{slug}`、
`POST /api/validation/graduation/{slug}/promote {confirm: true}`、`POST /api/validation/graduation/{slug}/demote {to}`、
`POST /api/validation/graduation-config`（仅管理员）。

## 1.5 策略体检单

「上线验证 → 策略体检」给策略做四项自动检查，再由 AI 红队列出最可能亏钱的原因。后台运行，几十秒到几分钟。

| 检查 | 怎么做 | 严重（bad） |
| --- | --- | --- |
| 未来函数 | 在 6 个时间点把数据截断后**重新计算**（用到 factor / predict 时，研究数据也按截断后的数据重算），截断前的每个信号和 record() 指标必须和完整数据一致；先跑两遍确认策略本身是确定的 | 任何一个截断点不一致 |
| 预热是否足够 | 同一个计分起点，分别给 1/4、1/2、1、2 倍预热，比较计分区间里的信号和指标 | 当前预热下一致率低于 95% |
| 成本翻倍 | 手续费、滑点、价差都翻倍再跑 | 收益由正转负 |
| 参数平台 | 每个数值参数上下挪 10%、20% | 挪 10% 夏普就掉到一半以下（孤峰） |

红队有大模型时用内置的「红队」角色（「角色库」里可以改它的提示词）；没有配置或调用失败时用规则清单：
体检结论、交易笔数、回撤、有没有止损、写死的时间戳、参数个数、利润是否集中在某个标的 / 标签 / 时段。

体检单记着代码哈希：改了代码，旧体检单就标为过期，毕业闸门不认。
验收：10 种埋了未来函数的因子（未来收益、居中均线、全样本标准化、全样本去趋势、未来方向标签……）全部被抓到，
3 种正常因子和普通均线策略没有误报（`tests/test_checkup.py`）。

接口：`POST /api/validation/checkup {slug, bars_limit?, use_llm?}`、`GET /api/validation/checkup?slug=`、
`GET /api/validation/checkup/{id}`（返回里 `stale` 表示代码已改过）。

## 1.6 智能调参

「参数优化」页右上角切到「智能调参」：勾选的参数只填起止范围（或手动列出候选值），optuna 用贝叶斯搜索（TPE）
在范围里试指定次数；勾选「同时压低最大回撤」改用 NSGA-II 多目标，最优取帕累托前沿里目标最高的那组。
和网格一样只用样本内选参，样本外和锁定区间只用来验。策略里也可以直接声明范围：

```python
PARAM_SPACE = {"fast": (4, 24), "slow": (24, 96, 4), "mode": ["a", "b"]}   # 元组 = 范围（第三个数是步长），列表 = 候选值
```

每一组试验（网格和智能调参都一样）都记进「研究纪律」的试验台账，试得越多 DSR 门槛越严。
验收：4 个参数、同样 16 次回测，在 4 段行情上智能调参的样本外夏普中位数不低于网格（`tests/test_optimize_bayes.py`）。
需要 `pip install optuna`（没装时智能调参会提示安装，网格不受影响）。

## 2. 仿真真实度

选同一个策略的纸面模拟和/或交易所模拟盘实验，平台用实验冻结的代码、参数和成本，在它实际跑过的那段行情上重跑一次回测，
逐笔配对成交，把收益差拆成：

- **延迟**：回测在下一根开盘成交；纸面模拟同样如此；交易所模拟盘在决策那根收盘时立即送单，差异算在这里。
- **滑点**：同一笔成交，实际成交价与行情价之差。
- **手续费**：实际手续费与回测成本模型之差。
- **拒单 / 部分成交**：按「持有到报告期末」估算错过的盈亏，是近似值。
- **其他**：总差异减去前五项，包括停机错过的信号、多出来的成交和复利效应。

报告还给出成本校准建议：滑点 = max(0, 实测滑点中位数 − 半个价差)，手续费率 = 实际手续费 / 成交额。
只用交易所模拟盘的成交来校准；样本少于 20 笔可信度「低」，50 笔以上为「高」。点「用作回测成本」后，
该交易所之后的回测默认用校准后的成本（需要确认）。

接口：`POST /api/validation/fidelity {session_ids}`、`GET /api/validation/fidelity[?strategy=]`、
`GET /api/validation/fidelity/{id}`、`POST /api/validation/fidelity/{id}/calibration {confirm: true}`、`GET /api/validation/calibration`。

## 3. 压力演练

在 4 个历史极端行情日上，用 1 分钟 K 线加速回放，走的是与模拟盘相同的下单链路（委托 → 模拟交易所回报 → 记账）：

| 场景 | 日期 |
| --- | --- |
| 3·12 新冠暴跌 | 2020-03-12 |
| 5·19 大跌 | 2021-05-19 |
| FTX 崩盘 | 2022-11-08 ~ 11-09 |
| 日元套息平仓 | 2024-08-05 |

可选注入故障：断线（重连后补单）、拒单、延迟和部分成交。每个场景给出收益、最大回撤、成交 / 委托、拒单、
断线时长、强平次数和损失、策略报错，以及「扛住了 / 没扛住」的结论。策略代码在隔离进程里运行，行情由平台进程取好后传入。
取不到历史数据时会换成形状相近的合成行情并明确标出，这时只能检验执行链路与故障处理。

接口：`GET /api/validation/stress/scenarios`、`POST /api/validation/stress {slug, scenarios?, faults?}`（后台运行）、
`GET /api/validation/stress`、`GET /api/validation/stress/{id}`。

## 4. AI 值守员

值守员逐笔解释实验的成交（为什么买卖、这笔平仓盈亏、是否部分成交），并对照策略说明书（SPEC.md）找矛盾：
只做多却出现空仓、超过杠杆或仓位上限、单日成交次数超限、说明书说该停了还在开仓、交易了说明书外的标的等。
规则检查总会运行；配置了大模型时再让模型补充解释，并标注模型名和提示词版本。值守员只看不动，结论进每天的 AI 晨报。

接口：`POST /api/validation/watcher/{session_id}?llm=true|false`、`GET /api/validation/watcher/{session_id}`、`GET /api/validation/watcher`。

## 5. 「问 AI」调用平台工具

平台的主要功能都登记成了「问 AI」可以调用的工具，说明集中在 `quant_agent/agents/platform_tools.py`：
每个工具写明用途、参数、什么时候可用、风险级别。系统提示里的工具说明由这份登记统一生成。

**按场景加载**：工具分为 5 个场景，每轮只把当前场景的工具交给模型。默认按页面选择（比如在「上线验证」页加载
上线验证 + 模拟交易），也可以在输入框左下角「+」菜单里手动勾选，或恢复按页面自动选择。
菜单里「查看全部工具说明」列出所有工具。

| 工具 | 名称 | 场景 | 风险 |
| --- | --- | --- | --- |
| list_strategies / get_strategy / list_backtests | 列出策略、读策略、回测记录 | 策略与回测 | 只读 |
| run_backtest | 跑回测 | 策略与回测 | 运行 |
| list_datasets / list_events | 研究数据集、事件流 | 研究数据 | 只读 |
| list_sessions / get_session | 实验列表、实验详情 | 模拟交易 | 只读 |
| start_session / stop_session | 启动、停止实验 | 模拟交易 | **需确认** |
| graduation / stress_result / morning_brief | 毕业闸门、演练结果、晨报 | 上线验证 | 只读 |
| fidelity_report / start_stress_drill / watch_session | 真实度报告、压力演练、值守员检查 | 上线验证 | 运行 |
| promote_strategy / apply_calibration | 晋级策略、应用成本校准 | 上线验证 | **需确认** |
| trade_breakdown | 交易分解（按标签、出场原因、标的、时段） | 策略与回测 | 只读 |
| run_checkup / start_tuning | 策略体检、智能调参 | 策略体检与调参 | 运行 |
| checkup_result / tuning_result | 体检结果（含红队意见）、调参结果 | 策略体检与调参 | 只读 |

**有后果的操作要人确认**：「需确认」的工具被调用时不会执行，只生成一条待确认动作，对话里出现确认卡片，
点「确认执行」才真正执行，点「取消」作废。只有发起人能确认，每个动作只能确认一次，全部记入审计。
没有任何实盘下单工具；停止实验默认先平掉全部持仓（模拟成交），可以选择只停不平。

接口：`GET /api/ai/tools`（目录）、`POST /api/ai/ask`、`POST /api/ai/ask/stream`（请求里带 `page` 和可选 `scenes`；
流里有 `{"type": "tool"}` 事件）、`GET /api/ai/actions/{id}`、`POST /api/ai/actions/{id} {approve}`。
