# QuantLab v 0.1 preview · 策略协议与数据口径

[English](Strategy-Protocol-and-Data-Conventions.en.md) | [文档索引](README.md) | [返回 README](../README.md)

本文定义：策略能看到什么、能输出什么、平台如何把输出变成成交、成交如何记账、指标怎么算。
回测、实时模拟、实盘对照三条路径共用这一套协议，差别只在“事件从哪里来”和“成交由谁撮合”。

---

## 1. 数值约定

- 记账、订单、成交、余额全部用 `Decimal`。**对外 JSON 中金额、数量、价格一律是十进制字符串**，例如 `"1009.79"`。
- 黄金样例（`tests/test_ledger.py::test_golden_fixture_cash_and_equity_exact`）：
  现金 1000，以 100 买入 1 个、手续费 0.1；以 110 卖出、手续费 0.11 → 现金 `899.9 + 110 − 0.11 = 1009.79`，逐位精确。
- 浮点只出现在统计指标（夏普、波动率等），且不回流到账本。
- 数量按 `qty_step` 向下取整，价格按 `price_tick` 取整；不足最小名义金额的订单拒绝（`ZERO_QUANTITY` / `BELOW_TOLERANCE`）。

## 2. 事件

每根 K 线是一个事件，带审计字段：

| 字段 | 含义 |
| --- | --- |
| `event_ts` | 事件所代表的时间（K 线收盘时间，毫秒 UTC） |
| `receive_ts` | 平台收到它的时间 |
| `sequence` | 同一来源内的单调序号 |
| `source` | `binance` / `okx` / `csv:<导入ID>` / `synthetic` |
| `instrument_id` | `BTC/USDT` |
| `raw_ref` | 原始记录引用（交易所 K 线开盘时间或 CSV 行号） |

规则：

1. **只用已完成事件**。策略在第 t 根 K 线收盘后被调用，只能读取 ≤ t 的数据；`history()` 在回测与实时模拟中行为相同。
2. **收盘信号、下一事件成交**：默认 `fill_at = next_open`，第 t 根产生的订单在第 t+1 根开盘价撮合。
3. **重复事件不重复成交**：`event_id` 去重；同一事件重放不会产生第二笔成交（`tests/test_acceptance.py::test_3`）。
4. **数据中断不下新单**：行情过期期间不调用策略、不产生订单（`test_7`）。
5. 缓存中同一 `(source, instrument, timeframe, event_ts)` 以**先收到的为准**，后到的不覆盖。

## 3. 策略能写的两种形式

### 3.1 规则 DSL（推荐，零代码）

结构化 JSON，平台解释执行，**不调用 `eval` / `exec`，不运行任何用户代码**。前端“逐项表单”与“JSON 视图”编辑的是同一个对象。

- 指标：`sma`、`ema`、`rsi`（Wilder）、`atr`（Wilder）、`highest` / `lowest`（通道）、`return`（区间收益）
- 条件：`gt` `gte` `lt` `lte`、`cross_above` `cross_below`、`consecutive`（最近 N 根都满足）、`all` `any` `not`
- 操作数：`{"ref": 指标, "lag": k}`、`{"price": "close", "lag": k}`、`{"const": x}`，均可带 `"mul"`
- 仓位：`{"mode": "weight", "value": 0.8}` 或 `{"mode": "quantity", "value": 0.01}`；`max_weight`、`qty_step`、`insufficient_funds`
- 风控：`stop_loss`、`take_profit`、`max_trades_per_day`、`drawdown_pause`
- 入场与离场同一根 bar 同时满足时**离场优先**；预热长度由指标自动推导，不足时自动补齐。
- 完整 schema：`GET /api/dsl/schema`；校验：`POST /api/dsl/validate`（返回字段路径 + 中文说明）。

### 3.2 Python 策略（聚宽风格 SDK）

```python
def initialize(context):
    g.fast, g.slow = 12, 48
    run_daily(trade, time="every_bar")
    run_timer(3 * 3600 * 1000)       # 每 3 小时触发一次 on_timer

def trade(context):
    closes = attribute_history("BTC/USDT", g.slow + 1, fields=["close"])["close"]
    ...
    order_target_percent("BTC/USDT", 0.8)

def on_bar(context, bar):            # 与 handle_data 等价的逐 bar 入口，额外收到本根 bar
    ...

def on_timer(context):               # 必须先用 run_timer(interval_ms) 注册，否则不会被调用
    ...

def on_trade(context, trade):        # 也可写 on_fill 或 on_order_filled，三者等价
    log.info(trade.signal_id, trade.amount, trade.price)

def snapshot(context):               # 可选：返回可 JSON 序列化的状态
    return {"fast": g.fast}

def restore(context, state):         # 可选：检查点恢复时收回状态（仅实时模拟会调用）
    g.fast = state["fast"]
```

- 入口：`initialize(ctx)` 启动一次；`handle_data(ctx)` 与 `on_bar(ctx, bar)` 都是逐 bar 入口，
  两者可同时存在（同时存在时都会被调用）。`on_bar` 的 `bar` 是当前时刻各标的**已收盘**的
  行情，与 `history` 同一口径，不含未来数据。
- 成交回报：`on_trade` / `on_fill` / `on_order_filled` 三个名字等价，成交后都会收到同一份成交。
- 定时：`run_timer(interval_ms)` 注册后才会有 `on_timer(ctx)`；触发粒度不会细于一根 bar。
- 检查点：`snapshot(ctx)` 的返回值随检查点保存，`restore(ctx, state)` 在恢复时收回。
  只有实时模拟会调用它们；回测不产生检查点。
- 策略版本：`get_strategy_version()` 或 `ctx.strategy_version_id` 取当前运行的策略版本 ID，
  便于把一次成交追溯到确切的版本。
- 下单函数：`order`、`order_target`、`order_value`、`order_target_value`、`order_target_percent`，
  均可带 `limit_price=`、`expire_bars=`；另有 `cancel_all`、`set_stop_loss`、`set_take_profit`。
- 订单类型：限价单可带 `time_in_force="GTC" | "IOC" | "post_only"`（IOC 只看下一根开盘，吃不到就撤；
  post_only 会吃单时撤单，成交一律按挂单方费率）和 `on_expire="cancel" | "market" | "chase"`
  （到期撤单 / 按开盘价改市价 / 按开盘价重挂，最多 3 次）。
- 买卖标签：下单时的 `reason=` 就是入场标签与出场原因，回测报告按标签、出场原因、标的、星期、小时分解。
- 多周期：`history(s, 50, "close", unit="4h")` 把本周期 K 线合成大周期，只给已完整收盘的；
  读别的标的（如用 BTC 判断大盘）把它也放进标的池即可。
- 移动止损与分段止盈：`set_trailing_stop(None, 0.05, activate=0.02)`、`set_roi({0: 0.06, 60: 0.03, 240: 0})`
  （键是持有分钟）。止损只会收紧，每根 bar 收盘后更新、下一根起生效。
- 持仓回调（都可选）：

  ```python
  def custom_stoploss(ctx, trade):   # 返回相对当前价的止损距离，如 0.03；只会收紧
  def custom_exit(ctx, trade):       # 返回原因字符串（或 True）就平仓
  def adjust_position(ctx, trade):   # 返回加仓（正）/ 减仓（负）金额，计价币
  def confirm_entry(ctx, security, side, amount, price, tag):  # 返回 False 否决这笔开仓
  ```

  `trade` 只读：`security / side / amount / entry_price / open_ts / bars_held / current_price /
  profit_ratio / max_profit_ratio / min_profit_ratio / entry_tag / entries / stop_price / is_short`。
- 交易所模拟盘：有止损价的持仓会在交易所挂一张**保护止损单**（Binance 现货止损限价、合约 Algo
  STOP_MARKET；OKX 条件单；Bybit 条件市价单，合约只减仓）。平台停了它也还在；止损价变化超过 0.1%
  先撤后挂；平台自己平仓前先撤掉它。交易所先触发时按交易所成交记账，出场原因 `exchange_stop`，
  平台不会再平一次。
- 组合保护（只拦开仓，不拦止损和平仓）：模块常量 `PROTECTIONS = [...]` 或 `set_protections([...])`。
  四种规则：`CooldownPeriod`（平仓后同一标的冷却 `stop_bars` 根）、`StoplossGuard`（`lookback_bars` 根内
  止损次数达到 `trade_limit` 就暂停开仓 `stop_bars` 根）、`MaxDrawdown`（近期已平仓交易回撤超过
  `max_allowed_drawdown`）、`LowProfitPairs`（某标的近期收益低于 `required_profit`，只锁这个标的）。
  `only_per_pair=True` 让止损暂停只锁出事的标的。锁定只看**已平仓**的交易，回测、纸面、模拟盘按同一份记录计算；
  被拦的开仓记为拒单，原因码 `PROTECTION_LOCK`。`is_locked(s)` 查询当前是否锁定。
- 动态标的池：`PAIRLIST = {"refresh_bars": 24, "filters": [...], "delist_exit": True}` 或 `set_pairlist(...)`。
  过滤器按顺序执行：`AgeFilter(min_bars)`、`PriceFilter(min_price)`、`VolatilityFilter(lookback_bars, min, max)`、`RangeFilter(lookback_bars, max)`、
  `VolumeFilter(lookback_bars, top, min_quote_volume)`。每次只用当时已收盘的数据重选，上市前的币选不到（没有幸存者偏差）。
  `get_universe()` 取当前池子；不在池子里的标的开仓被拒（`NOT_IN_UNIVERSE`），已有持仓照常管理。
- 下架公告：平台把「行情与数据 → 事件」里的下架公告按**公告可见时刻**交给内核，到点立刻移出标的池并拒绝新开仓
  （`DELISTED`）；`delist_exit=True` 时顺手平仓。实时运行每分钟查一次，不等下一根 bar 收盘。
- 同账户多策略（`live/netting.py`）：同一轮里各策略对同一标的的买卖先在内部按参考价对冲（不付手续费），
  只把净额合成一笔送交易所，成交按数量比例分回；可设账户总敞口上限（`ACCOUNT_RISK_CAP`，超出时从最大的加仓委托开始拒，
  减仓永远放行）。共享账户下不挂各策略自己的交易所保护止损。
- `context.portfolio` / `positions` **只读**，策略不能替换或修改（`test_portfolio_is_read_only`）。
- Python 策略在独立子进程执行：清空环境变量（看不到任何密钥）、CPU / 内存 / 文件大小上限、以 nobody 运行、可选断网。
  工作区管理员可关闭 Python 策略，只允许 DSL。

## 4. 策略输出：Signal 与 TargetPosition

无论 DSL 还是 Python，每次下单都先变成一个**信号**，信号携带一个**目标仓位**：

```json
{
  "signal_id": "4f1c9a…",              // sha256(run_id|strategy_version_id|instrument|event_id|n) 前 24 位，确定性
  "run_id": "run-…",
  "strategy_version_id": "sv-…",
  "instrument_id": "BTC/USDT",
  "event_id": "BTC/USDT:1791850800000",  // <标的>:<K 线收盘时间>
  "decision_ts": 1791850800000,
  "expires_at": 1791854400000,          // 默认 1 根 bar 后过期（signal_ttl_bars）
  "reason": "ma_fast 上穿 ma_slow",
  "target": {"instrument_id": "BTC/USDT", "kind": "weight", "value": "0.8", "unit": "fraction",
             "valid_until": 1791854400000},
  "order_type": "market",               // market | limit
  "limit_price": null,
  "status": "filled",                   // accepted | filled | partial | rejected | expired | tolerance | canceled
  "status_reason": "",
  "reason_code": ""
}
```

`target.kind`：`quantity`（base 数量）、`weight`（占权益比例）、`value`（计价币金额）、`delta_quantity`、`delta_value`。

**信号 ID 是确定性的**：同一 run、同一版本、同一事件上的第 n 个信号，ID 永远相同。
因此检查点恢复后重放事件，平台能识别“这个信号已经处理过”，不会重复成交（`test_8`、`test_snapshot_restore_does_not_duplicate_orders`）。

### 4.1 被拒绝的原因码

| reason_code | 含义 |
| --- | --- |
| `INSUFFICIENT_FUNDS` | 资金不足（**默认拒绝**；显式设置 `insufficient_funds=reduce` 才按可用资金缩量） |
| `INSUFFICIENT_POSITION` | 卖出数量超过持仓（不允许裸空） |
| `RISK_LIMIT` | 超过最大仓位权重 / 总敞口 |
| `RISK_TRADE_LIMIT` | 超过每日最大交易次数 |
| `RISK_PRICE_DEVIATION` | 成交价偏离参考价超过阈值（默认 20%） |
| `RISK_DRAWDOWN_PAUSE` | 回撤触发暂停 |
| `SIGNAL_EXPIRED` | 信号过期仍未成交 |
| `ZERO_QUANTITY` / `BELOW_TOLERANCE` | 取整后为 0 / 差额小于容忍度 |
| `NOT_TRADABLE` / `DATA_INCOMPLETE` / `END_OF_DATA` | 标的不可交易 / 数据缺失 / 数据结束 |
| `ENTRY_VETOED` | 策略的 `confirm_entry` 否决了这笔开仓 |
| `POST_ONLY_WOULD_TAKE` / `IOC_CANCELED` | post_only 限价会吃单 / IOC 没能立即成交，已撤 |

## 5. 风险层

信号 → **风险层** → 撮合。风险层独立于策略，策略无法绕过：

`max_position_weight`、`max_gross_exposure`、`max_trades_per_day`、`max_price_deviation`、`drawdown_pause`、
`stop_loss`、`take_profit`。目标超过上限时**裁剪**到上限（权重型）或**拒绝**（显式数量型），并记录原因。

## 6. 撮合模型

| 项目 | 规则 |
| --- | --- |
| 市价单 | 下一事件开盘价 ± 滑点（bps） |
| 限价单 | **保守 K 线模型**：买单要求 `low < limit` 严格穿越才成交，成交价 = 限价（maker）；`low == limit` 仅触价视为歧义，**不成交**；跳空直接低开时按开盘价成交 |
| 止损止盈 | 同一根 bar 同时触及止损与止盈，**止损优先**；固定止损、移动止损、custom_stoploss 取最近的一个，固定止盈与 ROI 同理 |
| 手续费 | 费率 × 成交额；`fee_currency=quote`（默认，从计价币扣）或 `received`（从收到的币扣，买入时扣 base） |
| 部分成交 | 资金或风控缩量时标记 `partial` |

## 7. 记账（双分录）

账户 `assets:<币>`、`trading:<币>`、`expenses:fees:<币>`、`equity:capital:<币>`，每种币种借贷恒等（`trial_balance` 为 0）。
回测报告的“账本与口径”页签展示试算平衡与全部分录。

- 出入金（`cash_flows` / 定投 `recurring_deposit`）记为资本变动，**不计入收益**。
- **期末未平仓不是已完成交易**：按最后价格估值，单列为“持仓中”，不计入胜率、盈亏比、持仓时长（`test_open_position_is_not_a_completed_trade`）。
  回测结束时**不会**自动平仓。

## 8. 指标口径

报告必带 `assumptions`（口径声明）：采样频率、年化因子、无风险利率、收益基准、撮合模型、资金不足处理、限价模型、止损优先、未平仓处理、预热长度、成本参数。

| 指标 | 定义 |
| --- | --- |
| 收益 | 有出入金时用**单位净值（时间加权 TWR）**：入金按当时净值折算份额；无出入金时等价于权益曲线 |
| 年化收益 | 几何年化；观测不足一年时提示可能夸大 |
| 波动率 / 夏普 | 逐 bar 收益，年化因子 = 每年 bar 数（1h = 8760） |
| 最大回撤 | 同一收益基准逐 bar 计算；给出**峰值时间、谷底时间、恢复时间**，未恢复时标注“尚未恢复”及持续时长 |
| 最差单日 | 按自然日聚合的日收益中最差的一天 |
| 持仓时长 | 只统计已平仓回合（开仓到平仓） |
| 总手续费 | 按币种汇总，并折算计价币 |

黄金样例（`test_golden_drawdown_details`）：净值 `[100, 110, 88, 99, 121]` → 最大回撤 20%，峰值第 1 根、谷底第 2 根、第 4 根恢复。

## 9. 研究纪律

- **锁定测试区间**：参数优化前切出末尾一段（`holdout`），调参全过程看不到它，只在选定参数后评估一次。
- **Purge / Embargo**：样本内外切点之后空出 `embargo_bars` 根不计分，避免指标窗口跨越切点泄漏信息。
- **Walk-forward**：按 `folds` 滚动训练 / 测试，报告每折样本外表现。
- 优化每完成一组参数写检查点，worker 崩溃后从断点继续。

## 10. 策略版本

`DRAFT → VALIDATED → FROZEN → ARCHIVED`。保存即登记版本，**内容不可改写**（改了就是新版本）。
每次运行记录 `strategy_version_id`；进入实时模拟要求版本已 `FROZEN`；`ARCHIVED` 版本不能再发起运行。

## 11. 目标仓位信封（为个人执行器预留）

平台本期不执行真实订单。`GET /api/runs/{id}/envelopes` 把权重型信号转换为信封，供用户自己的执行器使用：

```json
{"schema_version": 1, "signal_id": "4f1c9a…", "source_strategy_version": "sv-…",
 "instrument_id": "BTC/USDT", "target_weight": 0.8,
 "created_at": 1791850800000, "expires_at": 1791854400000, "reason": "…"}
```

执行器必须拒绝**过期、重复、乱序**的信封（参考实现 `live/envelope.py::EnvelopeValidator`），
并拒绝 `instrument_id` 不符合 `BASE/QUOTE` 格式、或带有未知字段的信封（信封是封闭协议）。
`POST /api/envelopes/validate` 的 `now` 缺省取**服务端当前时间**——过期判定不该由客户端自证；
真实执行器应使用自己的本地时钟，而不是信封里或请求里的时间。
并按自己的资金与持仓计算差额、施加自己的风险上限。数量型信号不直接转换（依赖当时价格与资金）。

## 12. 跟单（跟随者侧）与业绩口径

跟随模式三种，都由**跟随者自己的权益**折算，不照搬源策略的下单数量：

| 模式 | 仓位来源 | 必填参数 |
| --- | --- | --- |
| `fixed_amount` | 每个信号投入固定计价币金额（仍受 `max_weight` 与总敞口上限约束） | `fixed_amount` |
| `equity_ratio` | 跟随者权益 × 比例 × 源策略目标权重 | `equity_ratio` |
| `risk_budget` | 跟随者权益 × 风险预算 ÷ 止损距离 | `risk_budget`、`stop_loss_pct` |

- 源策略关闭/归档后的处置由 `on_source_closed` 明确指定：`keep`（维持现有仓位）、
  `stop_new`（不再开新仓）、`exit`（生成清仓计划）。**不设默认值**——不能靠"什么都不做"来兜底。
- 跟随账户业绩只由跟随者**自己的成交与资金流**计算（TWR 口径）。源策略的历史收益只能作为
  参考信息展示，字段上带 `reference` 前缀并显式标注"不是跟随账户业绩"。
  `live/copy.py::assert_not_source_returns` 会在生成报告前拦截把源收益当作业绩的写法。

## 13. 运行模式标签

| 模式 | 来源 | 是否“真实” |
| --- | --- | --- |
| `backtest` | 历史 K 线 | 否 |
| `paper` | 实时 K 线 + 模拟撮合 | 否 |
| `imported_live` | 用户导入的成交 CSV | 是（用户提供） |
| `readonly_live` | 只读 Key 同步的成交 | 是 |
| `testnet` | 交易所测试网 | 否，一律标为“测试” |
| `agent` | Agent 协作任务 | 不产生成交 |
| `analysis` | 只读分析 | 不产生成交 |

模式在 `platform/runs.py::MODES` 里显式白名单校验：拼写错误会直接报错，
而不是静默把真实数据当成模拟数据（或者反过来）。

全局横幅始终显示当前模式；没有真实成交数据时，实盘面板显示“未接入真实成交”，**不使用模拟曲线补位**。

## 14. Freqtrade 策略导入 / 导出

- 入口：我的策略 →「导入 Freqtrade」，或 `POST /api/freqtrade/check`（只检查）、`POST /api/freqtrade/import`（导入并自动体检）。
- 做法：策略类原样保留，只把 import 行换成兼容层 `quant_agent.sdk.ft`（DataFrame / Series 的常用操作、约 50 个 TA-Lib 指标、qtpylib、hyperopt 参数、`@informative`、`merge_informative_pair`、`stoploss_from_open`）。文件末尾接上 `initialize` / `handle_data`。
- 映射：`minimal_roi` → `set_roi`，`stoploss` → 交易所止损，`trailing_stop*` → 追踪止损，`custom_stoploss` / `custom_exit` 照常调用，`max_open_trades` 是可调参数（默认 3，资金均分）。hyperopt 参数变成 `PARAMS` 与 `PARAM_SPACE`，可以直接用参数优化。
- 时点：和 Freqtrade 回测一样，在收盘的 K 线上算信号，下一根开盘成交。逐 bar 运行时只给截至当前的数据（窗口取预热长度的 5 倍，至少 500 根），测试里 20 个常见策略的逐 bar 信号与整段向量化计算一致（≥99%）。
- 不支持（会报错，可让 AI 改写成平台原生策略）：做空、杠杆、`adjust_trade_position`、CDL 形态指标、pandas_ta、`self.wallets`。会被忽略并提示的：自定义入场 / 出场价、自定义下单金额、挂单超时等回调。
- 导出：`GET /api/freqtrade/export/{slug}` 恢复原来的 import 行、去掉平台接上的部分，把调参后的参数写回各个 Parameter 的 `default`，可以直接放回 Freqtrade 的 `user_data/strategies`。
- 行情：装了 ccxt 的服务器可以用 `ccxt:<交易所 id>`（如 `ccxt:kraken`）作为公共行情来源，只读、不下单。

## 15. 自适应与衰减

- 衰减监测（上线验证 →「衰减与重训」）：每小时对运行中的纸面模拟 / 模拟盘实验判定一次。日收益和每笔交易收益持续低于该策略最近一次完整回测的均值时，CUSUM 分数累积；衰减线取「从回测重采样出的正常路径在整个监测期（至少 14 天）里分数最高点」的 95% 分位，所以正常策略两周内被误标的概率约 5%。测试里一个明显失效的策略（日均亏 0.5%、每笔亏 0.8%）在 2 周内被标出的比例 ≥ 88%。运行不满 3 天只显示「观察中」。
- 正常区间：区间收益、最大回撤（按日收盘）、胜率、平均每笔收益，各自给出回测重采样的 5%～95% 区间和实际值的分位，用来解释分数为什么涨。
- 降级：判定为衰减时建议从晋级关卡退回一级并发「策略衰减」告警；降级要人点确认，平台不会自动停策略或降级。
- 模型定期重训：模型上设 `retrain = {enabled, every_days, min_ratio}`。到期后 worker 登记一个后台任务，面板截到重训时刻，只用已收盘数据训练（测试：把重训时刻之后的数据整体改掉，重训结果不变）。每次重训记一笔实验（来源 retrain），模型 versions 里带上一版的实验 id；样本外 RankIC 不低于旧版本 min_ratio 倍且通过准入才接替，冻结的模型另存为候选。
- 市场状态：按 BTC 日线，近 20 天年化波动率高于过去一年 80% 分位（且 ≥ 60%）为高波动，效率比 ≥ 0.3 为趋势，其余震荡。各策略按回测里「前一天的状态 → 当天收益」的 t 值得到各状态倍数（0.25～2），再按近期表现倾斜，得到建议权重。只是建议，不改仓位；多策略共用账户时由合仓调度器使用。

## 16. 微实盘

- 运行模式标签 `micro_live`（属于真实模式），执行方式 `live`。全局横幅和终端里显示「微实盘 · 真实资金」。
- 下单路径与交易所模拟盘相同（同一个 OMS、同一套止损单同步），只是换成真实地址的 Binance / OKX 现货客户端，外加资金上限、急停和止损必挂三道检查。
- 只做现货，交易对写成 `BTC/USDT`；带 `:` 的永续合约会被拒绝。
- 流程与开关见《运维与恢复手册》第 8 节。AI 助手只能查看微实盘状态和执行一键停止，没有启动微实盘或下单的工具。
