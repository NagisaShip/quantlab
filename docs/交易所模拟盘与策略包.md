# 策略包、交易终端与交易所模拟盘

这份说明对应执行侧第 1–3 阶段：策略包与运行内核、实时行情与交易终端、交易所模拟盘执行。
平台**没有实盘下单路径**：下单客户端里只有模拟环境的地址，调用方传不进别的主机。

## 1. 策略包 `.qstrat`

一个 zip 文件，里面是：

| 文件 | 内容 |
| --- | --- |
| `manifest.toml` | 名称、作者、版本、标的、周期、SDK 版本、依赖 |
| `strategy.py` 或 `strategy.json` | 策略代码（Python）或规则策略（DSL） |
| `params.json` | 参数 |
| `SPEC.md` | 说明书：策略在做什么、怎么用 |
| `data/*.csv` | 一小段确定性行情，用于核对 |
| `golden.json` | 标准答案：作者在这段行情上跑出的成交指纹、期末权益和代码指纹 |
| `lineage.json` | 可选：研究纪律台账里的试验次数、DSR 等 |

- **导出**：策略编辑器 → 更多 → 导出策略包。说明书在「编辑说明书」里改。
- **导入**：我的策略 → 导入策略包。平台先检查格式、安全、在隔离进程里重跑标准答案，看过报告再导入。
- 导入的策略一律**未批准**，要人看过代码后批准，才能进实时模拟。
- 标准答案没核对通过（代码被改过，或结果不一致）的包：能回测、能纸面模拟，**不能上交易所模拟盘**。

## 2. 命令行运行器 `qrun`

和平台同一个运行内核，同一个包在本机和平台上跑出的结果一致。

```bash
pip install -e .
qrun inspect  my.qstrat                 # 检查包、重跑标准答案
qrun backtest my.qstrat                 # 用包内数据片段回测（离线即可）
qrun backtest my.qstrat --market        # 用交易所公开行情回测
qrun paper    my.qstrat --minutes 60    # 实时行情 + 平台撮合
qrun demo     my.qstrat --exchange okx  # 交易所模拟盘
```

`qrun demo` 的密钥从环境变量读：`QRUN_API_KEY`、`QRUN_API_SECRET`，OKX 另需 `QRUN_PASSPHRASE`。
qrun 在本机进程里执行策略代码，只做静态安全检查，不做进程隔离。来源不明的包请导入平台运行。

## 3. 交易终端

实时模拟详情页就是交易终端：

- K 线：滚轮缩放、拖动平移、双击回到最新；买卖成交标在 K 线上；正在形成的那根每 3 秒刷新。
- 行情：优先 WebSocket 推送，断线自动重连并用 REST 补齐缺口；推送不健康时自动退回轮询。
- 下方标签页：持仓、委托（模拟盘才有）、成交、日志。
- 右侧：账户净值、成交方式、风控限额、滑点、对账结果。

环境变量 `QAGENT_STREAM=0` 可以关掉 WebSocket，全部走轮询。

## 4. 交易所模拟盘

真实行情 + 交易所的模拟资金：成交价、手续费、拒单都来自交易所。

| 环境 | 地址 | 价格是否跟实盘 |
| --- | --- | --- |
| Binance 模拟交易（Demo Mode） | demo-api.binance.com | 接近实盘 |
| Binance Spot Testnet | testnet.binance.vision | 不跟，只用于接口联调 |
| OKX 模拟盘 | www.okx.com + 请求头 `x-simulated-trading: 1` | 接近实盘 |
| Bybit 模拟交易（Demo Trading） | api-demo.bybit.com | 接近实盘 |
| Bybit Testnet | api-testnet.bybit.com | 不跟，只用于接口联调 |

**接入**：左侧「交易所模拟盘」→ 选环境 → 填模拟盘 Key。平台查一次余额，查得到才保存。
**启动**：实时模拟 → 成交方式选「交易所模拟盘」→ 选连接、设限额 → 启动。

安全设计：

- 密钥用平台主密钥加密，单独存文件，撤销时擦除；只在后台执行进程里解密，策略代码所在的隔离进程拿不到。
- 事前风控：单笔金额上限、每分钟笔数上限、当日亏损熔断。熔断后只减仓、不开新仓，要人手动解除。
- 客户端订单号由信号确定：网络超时**不重下单**，先查单；进程崩溃恢复后，在途订单也先查清楚。
- 资金预留：在途买单占用的资金不会被下一笔重复使用。
- 定期对账：交易所余额应等于「启动时余额 + 平台账本变化」，差超过 0.5% 就暂停开新仓并告警（比如你在交易所手动交易过）。
- 一键停止：先熔断，再把全部持仓的市价卖单送到模拟盘。
- 本次实验只动用你设定的资金；模拟账户余额不够时拒绝启动。

### 永续合约

- 标的写成 `BTC/USDT:PERP`（U 本位永续）。逐仓、单向持仓，默认 1 倍杠杆，`set_leverage('BTC/USDT:PERP', 3)` 对之后的开仓生效。
- 可以做空：`order_target_percent('BTC/USDT:PERP', -0.5)` 表示空头名义价值 = 权益的 50%。
- 资金费按交易所结算时刻记账（正费率多头付给空头），`get_funding_rate()` 只看得到已结算的费率。
- 强平价按逐仓公式计算（维持保证金率默认 0.5%）；回测、纸面模拟和压力演练都会在每根 bar 检查强平，
  强平按全部保证金损失处理，比交易所实际结果略保守。
- 交易所模拟盘：Binance、OKX、Bybit 的 USDT 永续都可以下单，开仓前自动设杠杆。

### 成交时点

回测和纸面模拟在信号的下一根 bar 开盘成交；交易所模拟盘在策略决策的那根 bar 收盘后立即送单。
两者的差异会在「上线验证 → 仿真真实度」里单列为「延迟」。成交记录带行情价（market_price）、下单数量和决策时间，
用来算滑点和部分成交。

### Bybit 模拟交易

- **获取 Key**：登录 Bybit 主站 → 右上角切到「模拟交易（Demo Trading）」→ 在模拟交易模式下打开 API 管理创建 Key
  （系统生成的 HMAC Key，勾选读写/交易权限）。只需要 API Key + Secret，不需要 Passphrase。实盘 Key 在模拟域名上验证不过，不会被保存。
  Testnet 的 Key 要在 testnet.bybit.com 单独注册创建。
- **地址**：只连 `api-demo.bybit.com` / `api-testnet.bybit.com`。客户端构造时再核对一次域名，
  没有任何实盘地址（`api.bybit.com` 等）的配置项。
- **支持**：V5 统一账户（UTA）。现货（`BTC/USDT`，category=spot）市价单，数量统一按标的币（`marketUnit=baseCoin`）；
  USDT 线性永续（`BTC/USDT:PERP` → category=linear、`BTCUSDT`）市价单，单向持仓（positionIdx=0）。
  下单前自动切单向持仓、尝试设逐仓并设杠杆；统一账户不支持逐笔切逐仓时忽略该错误、只设杠杆
  （此时保证金模式以账户设置为准，需要逐仓请在 Bybit 网页里把账户保证金模式设为逐仓）。
- **回报**：按客户端订单号（orderLinkId）查实时订单、查不到再查历史订单；手续费取成交明细（execFee / feeCurrency）。
  余额取统一账户钱包余额（walletBalance，不含未实现盈亏）。
- **行情**：实时模拟选交易所「Bybit」时，K 线和资金费率来自 Bybit 公共行情（api.bybit.com，只读、无密钥），
  盘中推送走 `wss://stream.bybit.com/v5/public/spot|linear` 的 `kline.<周期>.<交易对>` 频道，断线后 REST 补数。
  `qrun --exchange bybit` 同样可用。

## 5. 上线验证

模拟盘跑起来以后，到「上线验证」看真实度报告、跑压力演练、让 AI 值守员检查，满足条件后晋级。详见 [上线验证与AI工具.md](上线验证与AI工具.md)。

## 6. 验收前要做的事

在交易所创建模拟盘 API Key（Binance：网页切到「模拟交易」→ API 管理；OKX：切到「模拟交易」→ API，需要 Passphrase；
Bybit：主站切到「模拟交易」→ API 管理），
接入后用一个小资金的策略跑一天，看委托、成交、滑点和对账是否符合预期。
