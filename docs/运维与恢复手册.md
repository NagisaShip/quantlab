# QuantLab v0.1.0-preview.1 · 运维与恢复手册

[English](Operations-and-Recovery-Manual.en.md) | [文档索引](README.md) | [返回 README](../README.md)

本文面向部署与值守的人。平台分两层：**API（控制面）** 只受理请求、鉴权、查询状态；
**Worker（执行面）** 认领并执行所有长任务（回测、参数优化、实时模拟、账户同步、实盘对照、Agent 任务）。
两者只通过数据库通信，Redis 只用来“叫醒”worker，丢了也不影响正确性。

```
浏览器 ──HTTP──▶ API（qagent serve） ──写 runs 表 / LPUSH 唤醒──▶ PostgreSQL / Redis
                                                              ▲
                     Worker（qagent worker）◀─认领（FOR UPDATE SKIP LOCKED + 租约）─┘
                       └─ Python 策略子进程（独立进程、清空环境变量、CPU/内存/文件上限、降权、可选断网）
```

## 1. 部署

### 1.1 Docker Compose（推荐）

```bash
mkdir -p secrets
# 生成凭证主密钥（只生成一次；丢失 = 所有已保存的只读 Key 与模型密钥无法解密）
python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())" > secrets/secret.key
chmod 600 secrets/secret.key
cp .env.example .env            # 至少修改 POSTGRES_PASSWORD
docker compose up -d --build    # postgres → redis → migrate → api + worker
```

打开 `http://<主机>:8000`，**第一个注册的账号自动成为部署管理员**；之后默认只能凭邀请码注册
（`QAGENT_OPEN_REGISTRATION=1` 可改为开放注册）。

需要 Python 策略子进程彻底断网时：

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.isolation.yml up -d
```

该叠加文件只给 worker 授予 `SYS_ADMIN`（创建网络命名空间所需）。不叠加时其余隔离照常生效，
“设置与审计 → 平台”会如实显示“断网 = 否”。DSL 规则策略不执行用户代码，不受影响。

### 1.1.1 运行节点（云服务器，7×24 跑纸面模拟 / 模拟盘）

推荐 2 核 4G 起步、离交易所近的地区（东京、新加坡、法兰克福均可）。步骤：

1. 装 Docker 与 compose 插件，开时间同步：`timedatectl set-ntp true`（或 `apt install chrony`）。
   平台签名一律用交易所时间（worker 每 10 分钟测一次偏差），但偏差超过 5 秒仍会发「服务器时钟偏差」告警。
2. 按 1.1 起服务。compose 里所有服务都是 `restart: unless-stopped`：容器崩溃或服务器重启后自动拉起。
3. 在前面放 HTTPS 反向代理（Caddy 一行：`your.domain { reverse_proxy 127.0.0.1:8000 }`）。
   飞书 / 企业微信回调必须是公网 HTTPS 地址；Telegram 用长轮询，不需要。
4. 防火墙只开 443。在交易所后台把 API Key 的 IP 白名单设成这台服务器的出口 IP。

**恢复时间**：worker 每 20 秒续租（租约 60 秒）。服务器重启后，docker 拉起 worker，租约过期的实验进入 RECOVERING，
新 worker 从检查点恢复——通常 1–2 分钟内接着跑。停机前送出、还没拿到回报的订单按客户端订单号先查单，
**不重下**；交易所上的保护止损停机期间成交的，查到后补记账。

**主循环卡死**：worker 主循环超过 180 秒没有动静会自己退出（退出码 70），由 docker 重启。
`QAGENT_HANG_SECONDS=0` 关闭。

**失联告警**：看门狗跑在 API 进程里，每 30 秒检查一次；运行中的实验超过 2 分钟没心跳，就发「运行节点失联」告警，
并由 API 自己投递（这时 worker 已经发不了通知）。从断开到收到通知不超过 3 分钟。
在「设置 → 运行节点与机器人」能看到节点、时钟偏差、限频状态。

**限频**：每家交易所一个令牌桶（Binance 10 次/秒，OKX、Bybit 8 次/秒）。收到 429 / 418 时按 Retry-After 整体暂停，
期间本地等待最多 5 秒，等不及的请求不发出去、按拒单处理，避免被交易所封 IP。

**手机**：手机浏览器打开 `https://your.domain/#/board` 登录后「添加到主屏幕」。看板只读，
另有「停止」「停止并平仓」两个按钮，要输入确认字样才执行。

**聊天机器人**：「设置 → 运行节点与机器人」添加飞书 / 企业微信 / Telegram 机器人，生成绑定码后在聊天里发「绑定 123456」。
命令：`状态`、`为什么 1`、`停止 1`、`平仓 全部`；停止和平仓要回复 4 位确认码才执行（2 分钟有效）。
机器人以绑定用户的身份执行、记审计，审阅者只能查看。

### 1.2 单机开发

```bash
bash scripts/dev.sh                                         # Linux / macOS
powershell -ExecutionPolicy Bypass -File scripts\dev.ps1    # Windows
```

默认使用 SQLite（`~/.quant_agent/` 下）+ 本地轮询唤醒 + JSON K 线缓存，脚本会同时拉起 API 与 worker。
设置 `QAGENT_DATABASE_URL` / `QAGENT_REDIS_URL` 即可切到 PostgreSQL / Redis。

### 1.3 依赖锁定

- `requirements.lock`：运行时依赖。标 `[verified]` 的版本是当前完整测试套件实际运行的版本；
  标 `[pinned]` 的是二进制组件（psycopg-binary、pyarrow、uvicorn[standard] 附带的 websockets 等），
  首次在目标机器上安装成功后执行 `pip freeze > requirements.lock` 回写。
- `requirements-dev.lock`：测试与 lint。
- 前端：`web/package-lock.json`，构建用 `npm ci`。

## 2. 配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `QAGENT_DATABASE_URL` | SQLite（`$QAGENT_HOME/quantlab.db`） | `postgresql://user:pass@host:5432/db` |
| `QAGENT_REDIS_URL` | 空（本地轮询） | `redis://host:6379/0`，只做唤醒 |
| `QAGENT_HOME` | `~/.quant_agent` | 数据目录：K 线缓存、只读账户密文、策略文件 |
| `QAGENT_SECRET_KEY_FILE` / `QAGENT_SECRET_KEY` | `$QAGENT_HOME-keys/secret.key`（自动生成） | Fernet 主密钥；**与数据目录分开存放、分开备份** |
| `QAGENT_WORKER` | `external` | `external` = 独立 worker；`inline` 仅供测试 |
| `QAGENT_LEASE_MS` | `60000` | 租约时长；worker 失联超过该时间，任务转 `RECOVERING` |
| `QAGENT_WORKER_MAX_RESIDENT` | `50` | 单个 worker 同时驱动的实时模拟数量上限 |
| `QAGENT_PAPER_TICK_SECONDS` | `30` | 实时模拟拉行情间隔 |
| `QAGENT_EXCHANGE_MIN_INTERVAL_MS` | `75` | 同一进程内对同一交易所的外部行情请求最小间隔；本地缓存命中不等待 |
| `QAGENT_SANDBOX` | `subprocess` | Python 策略执行方式 |
| `QAGENT_SANDBOX_CPU_SECONDS` / `_MEMORY_MB` | `300` / `1536` | 单个策略子进程上限 |
| `QAGENT_SANDBOX_UID_DROP` | `auto` | 以 root 运行时子进程降权到 nobody；`off` 关闭 |
| `QAGENT_BAR_FORMAT` | `parquet` | 装了 pyarrow 用 Parquet，否则自动退回 JSON |
| `QAGENT_OPEN_REGISTRATION` | `0` | `1` = 开放注册 |

工作区级配额（并发运行数、每日回测次数、优化组合数、是否允许 Python 策略）在“设置与审计 → 工作区”里由管理员修改。

## 3. 日常检查

| 看什么 | 在哪里 | 正常状态 |
| --- | --- | --- |
| API 存活 | `GET /api/healthz` | `{"status":"ok","backend":"postgres"}`；只查数据库，不访问交易所 |
| 交易所连通 | `GET /api/health` | 各适配器 `reachable` |
| Worker 心跳 | 设置与审计 → 平台 → Worker；`GET /api/runs/workers` | 心跳在 1 个租约周期内；唤醒方式 `redis` |
| 策略隔离 | 同上（启动日志也会打印） | `进程/资源上限/降权/断网` 四项；容器默认“断网=否” |
| 网络可用性 | 全局横幅；`GET /api/market/network` | 部署满 72 小时前显示“待验证”，之后 AVAILABLE / DEGRADED / UNREACHABLE |
| 卡住的运行 | 设置与审计 → 运行 | 无长时间 `RECOVERING`；`QUEUED` 不应持续堆积 |
| 审计 | 设置与审计 → 审计日志 | 登录、成员变更、凭证增删、运行命令均有记录，不含明文密钥 |

Worker 日志会逐条打印 `run … 开始 / 完成，用时 …s`，失败带错误码与堆栈前 5 层。

## 4. 运行状态机与恢复语义

```
QUEUED ──认领──▶ RUNNING ──▶ COMPLETED / FAILED / CANCELED
   ▲               │  ▲
   │          pause│  │resume
   │               ▼  │
   │             PAUSED
   └── RECOVERING ◀── 租约过期（worker 崩溃 / 断网 / 被杀）
```

- **单租约**：认领用 `SELECT … FOR UPDATE SKIP LOCKED`，同一 run 同一时刻只有一个 worker 持有；
  每次写状态都校验 `lease_owner`（fencing），旧 worker 回来也写不进去。
- **检查点**：参数优化每完成一组参数写一次检查点；实时模拟每推进一根 bar 写快照
  （账本、挂单、策略 `g` 变量、已处理事件序号）。恢复从最近检查点继续，
  **已处理的事件按 `event_id` 去重，信号 ID 是确定性的，不会产生重复成交**（`tests/test_acceptance.py::test_8`）。
- **API 重启**不影响任何运行；**worker 重启**后，它持有的 run 在租约过期后进入 `RECOVERING`，被任意 worker 重新认领。

### 4.1 常见故障处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提交回测后一直 `QUEUED` | 没有 worker 在线 | `docker compose ps worker`；看“平台 → Worker”心跳；`docker compose restart worker` |
| 大量 `RECOVERING` | worker 反复崩溃（多为内存） | 看 worker 日志；调大 `QAGENT_WORKER_MEMORY` 或减小 `QAGENT_WORKER_SLOTS` |
| run `FAILED`，错误码 `TASK_FAILED` 且提示资源上限 | 用户策略超出 CPU/内存上限 | 属预期保护；让用户优化策略，或调大 `QAGENT_SANDBOX_*` |
| `QUOTA_EXHAUSTED` | 工作区配额 | 管理员在“设置与审计 → 工作区”调整 |
| 实时模拟显示“行情过期” | 交易所不可达 | 看网络横幅；数据中断期间**不会产生新订单**，恢复后从下一根已收盘 bar 继续 |
| 只读连接变为“已过期” | 交易所侧删除/禁用了 Key 或 IP 不匹配 | 让用户在“个人账户”重新检测或重新绑定 |
| Redis 宕机 | — | 自动退回数据库轮询（`--poll` 秒），功能不受影响 |

### 4.2 手动干预

```bash
# 取消一个运行（与界面“取消”相同，走命令队列，由持有租约的 worker 执行）
curl -X POST -H 'X-Requested-With: ops' -H "X-Workspace-Id: $WS" -b "qa_session=$TOKEN" \
     -H 'Content-Type: application/json' -d '{"command":"cancel"}' \
     http://127.0.0.1:8000/api/runs/$RUN_ID/commands
```

不要直接改 `runs.state`：状态写入要带租约校验，直接改库可能让两个 worker 同时执行。
确需人工修复时，先停掉全部 worker，再把卡住的 run 改回 `QUEUED` 并清空 `lease_owner`。

## 4.1 公网部署加固（发布前必须做）

- **注册**：生产环境保持 `QAGENT_OPEN_REGISTRATION=0`，只发邀请码；不要在公网直接开放注册。
- **TLS / 反向代理**：Nginx / Caddy 终止 TLS，设置请求体上限与连接超时；API 只监听内网。
- **限流**：在反向代理层限制登录、注册、上传与 AI 接口的 IP / 账号速率；应用层配额是第二道防线，不是唯一防线。
- **监控**：至少采集 `/api/healthz`、`/api/health`、`/api/runs/workers`、磁盘、内存、CPU、数据库连接数与 5xx；日志集中收集。
- **备份**：PostgreSQL / SQLite + 对象存储 + 主密钥分开备份；定期做恢复演练，不能只备份不验证。
- **多机**：worker 可以多机部署，但必须共用 PostgreSQL 与 Redis；上线前至少做一次多 worker 并发、worker 被杀、时钟漂移与网络分区压测。
- **隔离**：生产使用 Linux；Windows 开发环境只做进程隔离，不能作为生产隔离能力。

## 5. 备份与恢复

需要备份的东西有三样，**主密钥必须与数据分开保存**：

| 内容 | 位置 | 方式 |
| --- | --- | --- |
| 数据库 | PostgreSQL `qagent` 库 | `docker compose exec postgres pg_dump -U qagent -Fc qagent > qagent-$(date +%F).dump` |
| 数据目录 | volume `appdata`（`/data/home`） | 只读账户密文（`account-secrets/*.enc`）、策略文件、K 线缓存 |
| 主密钥 | `secrets/secret.key` | 离线保存（密码管理器 / 保险柜），**不要**和上面两样放同一处 |

K 线缓存可以丢，会重新拉取。只读账户密文丢失只需让用户重新绑定。

恢复：

```bash
docker compose down
docker compose up -d postgres redis
docker compose exec -T postgres pg_restore -U qagent -d qagent --clean < qagent-2026-10-13.dump
# 还原 appdata volume 与 secrets/secret.key
docker compose up -d     # migrate 会补齐新版本的迁移
```

恢复后检查：能登录；“个人账户”里的连接点“重新检测”能通过（说明主密钥对得上）；
运行列表中原 `RUNNING` 的实时模拟会在一个租约周期后进入 `RECOVERING` 并自动续跑。

### 5.1 主密钥轮换 / 泄露

1. 生成新密钥；2. 让所有用户撤销并重新绑定只读连接（撤销 = 删除密文文件）；
3. 部署管理员在“模型配置”页重新录入模型密钥；4. 替换 `secrets/secret.key` 并重启 api 与 worker。
同时提醒用户到交易所后台删除旧 Key——平台撤销只删除平台侧凭证，交易所侧 Key 仍然有效。

## 6. 数据库迁移

- 迁移文件：`src/quant_agent/platform/migrations/000N_*.sql`，按序号执行，记录在 `schema_migrations`。
- `qagent migrate` 独立执行；API 与 worker 启动时也会检查。PostgreSQL 上用 advisory lock，多个进程同时启动不会重复执行。
- 新增迁移只追加文件，不改已发布的文件。

## 7. 安全基线

- 默认**关闭真实下单**：只读客户端只有 GET 方法，`tests/test_acceptance.py::test_10` 与
  `tests/test_live.py::test_readonly_clients_have_no_order_path` 守护这一点。唯一的真实下单路径是「微实盘」（见第 8 节），
  服务器不设 `QAGENT_MICROLIVE=1` 时它整个不可用。
- 开启了交易或提现权限的 Key 在检测阶段被拒绝且**不保存**。
- 凭证用独立主密钥加密，每个连接一个密文文件；数据库里只有 `connection_id`、掩码与 `secret_ref`。
- CSV 导入拒绝以 `= + - @` 开头的公式单元格；导出时统一中和。
- 会话 Cookie `HttpOnly + SameSite=Lax`；写请求必须带 `X-Requested-With`；工作区成员关系逐请求校验；审阅者只读。

## 8. 微实盘（真实资金，小额）

微实盘默认关闭。打开需要三层同时满足，任何一层不满足都拒绝启动：

1. **服务器开关**：环境变量 `QAGENT_MICROLIVE=1`（docker-compose 里 api 与 worker 都要设）。不设时页面只显示说明。
2. **工作区开关**：管理员在「微实盘」页读完风险告知，输入「我已了解实盘风险」后打开。告知文字改动后需要重新确认。
3. **没有急停**：页面「一键停止」或在 `QAGENT_HOME` 下放一个 `microlive.KILL` 文件。

实盘 Key：只支持 Binance、OKX 现货。接入时检查三项：能交易、**不能提现 / 划转**、**绑定了 IP 白名单**（白名单填运行节点的公网出口 IP）。三项任一不满足即拒绝且不保存。每次启动前会重新检查一次并读余额。

资金上限：每个毕业策略单独一档，默认 100 → 300 → 1000（USDT），硬上限 10000。在当前档跑满 14 天且最大回撤不超过 10% 后，管理员才能升一档。上限按交易所余额核对：本次实验已花的报价币 + 新单金额不能超过上限。减仓、平仓永远允许。

每单都要挂交易所止损单；止损单被交易所拒绝时，该实验立即停止开新仓（不允许裸仓），并发告警。

启动：只有晋级关卡里「毕业」、当前版本已批准的策略能启动。管理员生成启动摘要后得到 6 位确认码（5 分钟有效、错 3 次作废），再输入确认码和「确认实盘」才会启动。所有操作写审计日志（`microlive.*`）。

紧急处置：
- 页面「一键停止」：所有微实盘实验平仓并停止，之后拒绝新的启动。任何可写成员都能按。
- 平台进程不可用时：直接到交易所后台撤单、平仓、删除 Key；然后在 `QAGENT_HOME` 放 `microlive.KILL`，防止平台恢复后重新开仓。
- 解除急停：删除 KILL 文件，管理员在页面上输入确认语解除。
