## 本轮已修复

1. **审批状态被历史错误遮挡**：后端明确等待用户时，页头显示“等待输入”，不再被前面的可恢复错误覆盖。原工具错误卡仍保留。
2. **本地产物未计入成果证据**：识别成功 `local_chart` 的本机图片结果，以及成功 `workflow_import_data` 返回的文件 SHA-256；不会将普通文字“已生成”、失败工具、截断 JSON 或其他工具的相似字段当成成果。
3. **本地模型设置冗余**：本地模式合并为一个服务商列表，新增入口统一，移除不适用的成员共享说明。已有服务商和路由保持兼容；账号模式仍保留原有分层管理。
4. **CSV 工具契约缺失**：模型看到的工具说明与 schema 明确要求 `.csv` 文件名，保留服务端严格校验和不覆盖行为。此项降低错误概率，不宣称能阻止所有模型参数错误。
5. **图表没有纵轴刻度**：折线图和柱图增加轻量网格与数字刻度，保留原配色和零基线。

实际会话消息回放至 seq 18：修复后的状态为“已生成”，包含 2 条产物证据；回放至 seq 19：状态为“等待输入”。

## 尚需改进，按优先级

| 优先级 | 已观察问题 | 建议与下一轮验收标准 |
|---|---|---|
| P1 | 工具结果正确，最终文字仍补出错误平均值，且声称“全部由工具计算” | 数字结论绑定具体计算结果；新增指标必须实际计算。相同任务无需用户追问即可得到 1.1882%，证据之外的数字不标为工具验证 |
| P1 | 无关“删除 0 条回测记录”审批 | 审批前校验目标非空，删除类工具仅在用户明确要求清理时进入候选；空目标返回可恢复参数错误，不制造审批。不能通过放松审批来解决 |
| P2 | `<target_placeholder>` 出现在最终回复 | 检查供应商原始输出与协议解析边界，区分协议残留和合法代码示例，再做定向修复；本轮没有用全局删尖括号来掩盖问题 |
| P2 | 首页“自动”仍进入偏策略的能力叙述；停止提示提到“当前代码”，但任务只是解释概念 | 通用问答、表格研究和策略任务按真实意图区分；提示根据有无代码变化生成 |
| P2 | 顶部会话名称生成后未立即更新，刷新才显示新名称 | 同步服务端标题更新与本地输入状态；不要覆盖用户正在编辑的标题 |
| P2 | 文本消息逐条显示“已回复 / 无运行证据”，中间回复噪声较多 | 默认只保留回合级状态；工具详情与证据按需展开。纯问答不应反复提示“无运行证据” |
| P2 | 提交时状态只显示“默认模型”，而输入框选择了具体模型 | 展示实际使用的模型；发生降级时标明切换，而不是让用户猜测 |
| P2 | 运行中输入提示是“排队，完成后发送” | 增加明确的“补充当前任务”语义，区别于下一轮排队；长任务下一工具步骤前应接收纠正 |
| P3 | 图表零基线使 100—106 的小幅变化较平 | 后续提供自动范围或用户指定范围，并明确显示纵轴，避免静默夸大变化 |

## 与 Claude Code / Codex 的体验对标

Claude Code 官方文档明确区分立即停止和运行中纠正：纠正可在当前动作结束后、下一步之前被接收；也提供变更 diff 审查。这是 QuantLab 应学习的“用户随时掌控任务”体验。当前实测停止可用，但运行中输入只承诺下一轮排队，不等同于中途纠偏。[Claude Code 桌面文档](https://code.claude.com/docs/en/desktop)

Codex 官方文档强调对具体 diff 给出优先级明确、可操作的审查结果，审查本身不修改工作树。对 QuantLab 的对应建议是：研究结束时集中展示数据来源、计算结果、生成文件和失败/恢复摘要，让用户能检查成果是否成立，再决定下一步。[Codex Code Review](https://learn.chatgpt.com/docs/code-review)

保持简洁的具体方向：默认一个输入框、一条当前状态、一个成果入口；模型、上下文和停止放在输入框底栏；中间工具调用默认折叠；设置按本地/账号模式裁剪。优先把现有能力做可靠，不照搬竞品全部导航或面板。
