## 1. 总表

| 能力 | Linux（root / 容器） | Linux（普通用户） | Windows（开发环境） | 说明 |
|---|---|---|---|---|
| 独立子进程 | ✅ | ✅ | ✅ | 策略在独立 Python 子进程中执行 |
| 环境变量清理 | ✅ | ✅ | ✅ | 子进程只拿到最小环境 |
| 临时工作目录 | ✅ | ✅ | ✅ | 每次运行独立目录，结束后清理 |
| 超时终止 | ✅ | ✅ | ✅ | 超过时间限制强制结束 |
| CPU / 内存 / 文件大小上限 | ✅ | ✅ | ❌ | 依赖 POSIX `setrlimit` |
| 降权执行（nobody） | ✅ | ⚠️ 需权限 | ❌ | 依赖 POSIX uid/gid |
| 新会话 / 进程组 | ✅ | ✅ | ❌ | 依赖 POSIX `setsid` |
| 网络命名空间 / 断网 | ✅ | ⚠️ 需权限 | ❌ | 依赖 Linux netns |
| 策略源码 AST 审查 | ✅ | ✅ | ✅ | 禁止网络、文件 IO、危险导入 |
| 策略包完整性校验 | ✅ | ✅ | ✅ | 代码 SHA-256 / `.qstrat` 清单 |

> 图例：✅ 生效；⚠️ 取决于权限 / 配置；❌ 不生效。

## 2. 代码依据

- `src/quant_agent/platform/isolation.py`
  - `_preexec()` 在非 POSIX 平台直接返回 `None`；
  - POSIX 下设置 `RLIMIT_CPU`、`RLIMIT_AS`、`RLIMIT_FSIZE`、`setsid`、降权与可选 netns。
- `src/quant_agent/platform/sandbox_exec.py`
  - 通过 stdin/stdout 行 JSON 与子进程通信；
  - 子进程只执行策略加载、回测 / 优化 / 纸面模拟等白名单操作。
- `src/quant_agent/sdk/runner.py`
  - `FORBIDDEN_NAMES` 与 AST 检查拦截危险导入 / 调用；
  - 策略文件只能通过受控 API 访问数据与下单意图。

## 3. 平台如何展示

- 顶部运行状态中的「策略隔离」会显示：
  - `已验证`：隔离探测通过；
  - `部分生效`：只做到进程隔离 / 环境清理，缺少资源上限或网络隔离。
- Windows 开发环境通常显示「部分生效」，这是预期行为，不是故障。

---

## 4. 部署建议

### 生产 / 公开试用

- 使用 **Linux + Docker**；
- 以非 root 运行 API / worker，但隔离子进程需要足够权限设置 rlimit / netns；
- 配置独立网络、只读根文件系统、资源配额与日志采集；
- 不要把宿主 Docker socket 挂进容器。

### Windows 开发

- 仅用于开发与演示；
- 不要依赖 Windows 下的资源上限 / 断网能力；
- 微实盘 / 真实资金相关操作应在 Linux 部署环境完成。

---

## 5. 已知限制

1. 隔离能力与操作系统、内核、容器权限强相关，不能用一个“五层隔离”概括所有环境。
2. `probe()` 的探测结果只代表当前进程权限下的能力，不代表其他部署环境。
3. 微实盘不依赖策略沙箱的资源上限，但依赖交易所止损、Key 权限和资金上限；两者是不同层面的防线。
4. 真实永续使用独立的服务器开关、密钥目录、期货账户自检、敞口/杠杆/日亏限制、交易所止损和 `real_perp.KILL` 急停；它同样不等于生产级交易所风险引擎。
