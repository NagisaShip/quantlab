## 7.1 本次修复的真实问题

- **参数优化检查点**：排名在全部组合算完后才附加，之前恢复出的行缺少 `in_rank` / `out_rank`；现在最终行会写回检查点。
- **微实盘 Key 权限事后放大**：重新自检发现提现 / 划转权限时，立即擦除密文并撤销连接，而不是只标成 `error`。
- **行情横幅**：`mode_label` / `live_enabled` 现在真实反映微实盘服务器开关与工作区开关，不再固定写“没有真实下单路径”。
- **静态站点容错**：`web/dist/assets` 正在被 Vite 清空重建时，API 启动不再因目录瞬时缺失而失败。
- **E2E 登录流程**：登录页改为“介绍页 + 右侧抽屉”且支持用户名登录后，测试改为先打开抽屉、定位 `autocomplete=username`，退出登录也从账号菜单进入。
- **纸面模拟 E2E**：改为应用内确认框，并按“行情”下拉的实际位置选择 `demo`；暂停前等待服务端真正进入 `running`，避免把“恢复中”的禁用按钮当故障。
- **工作区被误清空**：前端曾把任何“403 + 文案含工作区”都当成无效工作区，导致关闭研究导师后收到 403 时被静默切回另一个工作区；现在只在服务端返回 `details.workspace_id` 时清空选择。研究流程 E2E 覆盖了导师关闭提示。
- **研究流程覆盖**：新增 `qa:research` 审计，将 44 个 `PageKey` 明确分成 30 个直接入口、8 个上下文详情页与 6 个非研究页面。

## 8. 已知非阻塞项

1. 上游库弃用警告（FastAPI / Starlette / httpx）不影响当前功能。
2. `page-research` 约 624KB，仍有 >500KB chunk 提示；循环 chunk 警告已消除，建议后续继续拆共享研究组件。
3. 本地 Windows 环境的 Python 策略隔离只有进程隔离，资源上限 / 降权 / 断网需 Linux。
4. 英文巡检会保留系统错误文本与运行时路径，这是环境输出，不是界面翻译缺口。
5. `pytest --collect-only` 的收集数会随可选依赖（torch / lightgbm 等）与环境变化，发布判断以完整运行结果为准。
