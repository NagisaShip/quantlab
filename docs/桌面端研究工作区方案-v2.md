## 3. 后续阶段（按依赖顺序）

### P1 关窗语义与窗口状态（已完成）

沿用 v1 设计，按当前实现调整：

- 三个动作：关闭窗口（隐藏到托盘，任务继续）/ 退出应用（停后端）/ 停止任务（只取消 run）。
- `POST /api/local/shutdown` → 有任务返回 `409 {code:"tasks_running", tasks:[…]}`；
  无任务保持 `200 {stopping:true}`；兼容旧 pywebview 的 `detail` 字段。
- 有任务点退出：弹「隐藏到托盘（默认）/ 完成后退出 / 取消」；`pending_quit` 每 5s 轮询
  `/api/local/tasks`，清空后 shutdown + exit；托盘菜单显示等待状态并可取消。
- 窗口状态：`%APPDATA%\com.quantlab.desktop\window.json` 保存 size/position/maximized，
  启动校验在屏幕内；与无边框标题栏、托盘恢复配合。
- 验收：三种偏好 × 有/无任务矩阵；`curl` 409 结构；强杀/崩溃后恢复提示。

### P3 成果固定、版本与专注阅读（已完成）

### P4 Agent 状态语义与长任务（已完成）

- 状态五态：等待输入 / 排队中 / 生成中 / 已生成 / 执行失败；
  “已生成”以 run + artifact 存在为条件，只有文字回复显示“已回复”。
- 上下文：现有 AskAI 上下文条扩展到 Agent 页/右栏；研究、节点、引用成果三者可见可移除。
- 长任务：消息绑定 run_id；离开页面/刷新后按 run 状态与产物恢复；
  全局运行横幅与标题栏最近结果保持；关窗继续、退出有任务需处理（P1 保证）。
- 验收：五种状态与后端一致；不能说“完成”却没有产物；长任务恢复。
