# 模型调用失败与「规则降级」排查

日期：2026-10-21。适用于账号模式与本地模式的 AI 研究室、因子 / 模型 / 组合 / 执行研究室、团队评审与「问 AI」。

## 先看现象怎么读

对话里出现「**规则降级**」表示这一轮没有拿到模型回答，平台改用模板或规则继续。现在它会先给出一句**可行动的原因**，再列当前仍可用的功能；如果是临时故障，点这条消息旁的「重试」即可重发，不会丢对话。

典型原因与处理：

| 界面提示 | 含义 | 处理 |
|---|---|---|
| 未配置任何模型密钥 | 没有服务商密钥或路由为空 | 设置 → 模型：添加服务商、保存密钥；设置 → 模型 → 路由：选默认模型 |
| 模型网关缺少会话标识（x-opencode-session），已自动重试 | OpenCode 网关偶尔要求会话头；平台已自动换新会话标识重试一次 | 若仍失败，稍后再试或检查 API 地址 |
| 模型密钥无效或没有权限 | 401 / 403 | 重新保存密钥；确认账户有该模型权限 |
| 模型接口或模型名不存在 | 404 或地址写错 | 检查 base_url（OpenAI 兼容一般以 `/v1` 结尾）与模型 ID |
| 模型服务限流，稍后重试 | 429 | 等一会儿或换降级链里的下一个模型 |
| 模型服务暂时异常（HTTP 5xx） | 服务商故障 | 稍后重试 |
| 这次对话太长，超出模型上下文 | 上下文窗口超限 | 平台会先自动压缩较早工具输出并原地重试一次；再失败可手动压缩上下文或新开对话 |
| 连不上模型服务（网络中断或超时） | TLS/连接被网关或网络中断 | 稍后重试；必要时检查代理 / 网络 |

## 本轮修复

- 模型调用失败时**保留服务商响应正文**（截断），不再只显示 httpx 的 `Client error '400 Bad Request' … For more information check: https://developer.mozilla.org/...`；界面上的原因会去掉 MDN 链接并整理成中文。
- OpenCode 网关返回 `400 MissingSessionID` 时自动换新 `x-opencode-session` 重试一次（`/responses` 与 `/chat/completions` 两条路径都覆盖）。
- 模型明确返回上下文超限 / 请求过大时，压缩较早工具输出、丢弃历史思考内容后**原地重试一次**，而不是直接降级。
- 一个候选模型都没有时，报「没有可用的模型：请在 设置 → 模型 添加服务商并在 路由 选择默认模型」，不再出现「所有模型均失败:」后跟空行这种谜语。
- 团队评审、模板生成等降级原因同样使用新文案；不会再把 MDN 状态码链接当成原因。

## 仍然要区分的能力边界

- 「规则降级」不是错误弹窗：没有模型时平台会用真实数据做规则分析，仍可 `/回测`、`/解释`、自动迭代、改代码存版本；只是不做自由对话与开放式设计。
- 模型服务商自身的账单、限流与地域可用性不归平台控制；平台只在调用前检查工作区 / 成员额度。
- 若「设置 → 模型 → 测试」返回服务商原始错误，请先按上表定位，再检查该服务商的模型 ID 与控制台状态。

## 思考模型的工具回合：reasoning_content 必须传回

症状：`模型服务拒绝了这次请求（HTTP 400）：Upstream request failed: [invalid_request_error] The reasoning_content in the thinking mode must be passed back to the API.`

原因：OpenCode 网关把 Responses 请求转发给 DeepSeek 思考模型时，工具回合里的 assistant 消息必须带回上一轮的思考内容（`reasoning_content` / Responses 的 reasoning item）。旧实现只回传 assistant 正文与 `function_call`；网关无法从会话状态里关联到那轮思考时就返回 400。同一会话里能复用网关状态时不一定复现，所以表现为“偶发”。

修复（`llm/providers.py`）：

- Responses 协议：assistant 消息带工具调用时，在 `function_call` 之前插入 `reasoning` 项；优先使用上一轮响应里的原始 reasoning item（`provider_blocks`），没有摘要时用占位文本，保证字段存在。
- Chat Completions 协议：DeepSeek / OpenCode 目标的 assistant 工具消息带 `reasoning_content`（即使为空也带字段）。
- 非思考网关（普通 OpenAI 兼容）不会凭空插入 reasoning 项，避免被服务商拒绝。

如果仍看到这个 400：确认服务已重启到新版本；或在「设置 → 模型」把默认模型换成清单里第一个可用的。

## 默认模型选择

AI 研究室等入口在用户没有单独选择模型时使用「默认」：默认模型 = 当前模型清单里的第一个（优先已配置密钥的），顺序与设置页一致；只有完全没有模型时才回落到全局路由。这样路由被改动不会悄悄改变默认模型，也更容易复现问题。模型菜单里的这一项已由「跟随全局路由」改名为「默认」。
