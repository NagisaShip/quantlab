# 自定义函数卡片规范 v1

## 最小完整示例

每张卡片是一份UTF-8 Python源码。不要在模块顶层运行训练、联网、加载大文件或读写数据。平台用AST读取字面量NODE，发现卡片时不会导入用户代码。

```python
NODE = {
    "kind": "user.scale",
    "version": "1",
    "title": "数值缩放",
    "category": "自定义",
    "description": "新增scaled字段，保留原记录。",
    "inputs": {"data": {"type": "table"}},
    "outputs": {"data": {"type": "table", "schema": {"type": "array"}}},
    "parameters": {
        "type": "object",
        "properties": {"column": {"type": "string", "default": "value"},
                       "factor": {"type": "number", "default": 1}},
        "additionalProperties": False,
    },
    "requirements": [],
}

def execute(ctx, inputs, params):
    out = [{**row, "scaled": float(row[params["column"]]) * params["factor"]}
           for row in inputs["data"]]
    ctx.log(f"完成{len(out)}行")
    return {"data": out}
```

## 接口与参数

kind必须以字母开头，只含字母、数字、点、下划线和短横线，长度不超过80；建议用`user.功能名`。version为短字符串，修改公共实现时增加版本，实验性修改另建kind。已发布同名同版本源码不可覆盖。

inputs/outputs是具名端口字典，至少一个输出。每个端口声明type，例如table、model、predictions、report或config；输入any可接收任意类型。输入默认必需，optional输入用required=False。role表示train/validation/test等用途；输入role要求精确匹配，forbid_roles禁止指定用途。不要把测试标签转换成无用途输入来规避检查。

execute必须同步定义，参数名称严格为ctx、inputs、params，返回字典的键与声明输出完全一致。值必须可JSON序列化，不含NaN/Infinity、对象句柄和隐藏本地路径。表格工件是JSON，百万行或大型张量不宜直接物化；模型、图像等二进制文件通过ctx.save_file返回带哈希的引用。

parameters是object schema，支持type、properties、required、additionalProperties、enum、minimum、maximum、minLength、maxLength、items、minItems、maxItems、default。不支持完整JSON Schema标准的所有关键字。默认值由平台填充，实际值运行时校验。绑定参数使用实例bindings：`{"factor":{"input":"config","path":["factor"]}}`；需要在NODE.inputs中声明并连接config端口，记录可区分绑定与手填来源。

端口schema校验实际输入输出。type和role负责静态连线检查；列名、单位、币种、频率、可用日期、实体标识和缺失处理应由专门的检查卡片在运行时核验，不得认为同为table就已满足研究口径。

## 执行上下文与依赖

ctx.file(name)读取工作区显式导入的文件，限定在输入根目录；ctx.work是本次临时目录；ctx.seed为工作流种子；ctx.log(message)写可见日志；ctx.save_file(path)保存二进制研究工件。不要修改输入对象，不读取未声明的全局状态或环境凭证。需要随机数的库必须用ctx.seed初始化各自的生成器。

requirements声明所有第三方包及版本约束，例如`["numpy>=1.26,<3"]`。只支持PyPI包名、可选extras及版本约束，不接受URL、路径、命令参数和私有凭证。执行环境需预先安装依赖；导出器解析传递依赖并打包当前系统/Python的wheel，安装包不可取得时导出失败。

file_params列出文件名参数，例如`["file"]`，影响文件内容哈希、缓存失效和完整导出。动态绑定文件名时，在workflow.resources中显式列出所有输入资源。远程数据源可声明capabilities.network=True，但必须先将数据物化为离线输入后才能形成完整离线包。依赖平台内部服务且没有独立实现的卡片声明portable=False。

## 调试、版本与子流程

先执行代码与接口差异检查，再发布。对照典型输入、空值、异常值、重复键、用途与年份边界运行；检查不应只是重复实现公式。实例替换版本后原连线保留，端口消失时标红并阻止执行，不能默默删除连接。

固定工件和历史输入只用于debug，正式实验不接受固定输出。运行记录保留代码、参数、输入、文件哈希、种子与依赖版本。模型训练只使用train，参数/阈值选择只使用validation；最终test交给冻结模型的预测与评价节点。

封装子图生成NODE.subflow及显式边界映射，执行由运行器递归分派。其execute只允许标准的`return ctx.run_subflow(inputs, params)`，不能将它误当成可任意改写的普通执行函数；修改内部算法请展开或编辑subflow定义后发布新版本。子流程内仍使用普通函数卡片，导出会递归收集全部代码与资源。

自定义卡片是可信代码扩展，独立进程不限制作者主动访问系统文件或网络。提供给不可信作者的服务应增加系统级隔离；不能把当前超时、环境凭证剥离和路径辅助方法当作安全沙箱。


## 模块化研究工作台补充

`level="module"` 表示完整研究模块，`level="function"` 表示基础函数；内部辅助节点可标记 `internal`。界面默认展示完整模块，按需展开编辑后重新封装。参数可增加 `title`、`description`、`visible_when`；任意JSON值可指定 `widget="json"`。

输出端口可使用 `role_from="data"` 继承输入用途，或使用 `role_from=["left","right"]` 合并输入用途。合并时 test、validation 优先于 train，不能通过整理或连接把测试用途抹去。端口 `semantics` 声明单位、时区、实体标识或模型后端等，目标端声明的具体值须与来源匹配；实际数据内容仍需检查。

`subflow.parameters` 将公开参数映射到 `{node, parameter}` 或端点列表，一个公开值可更新多个内部函数。重新封装时可选择公开参数，未填写的必填项自动公开。运行时绑定参数在实际输入可用后解析；若需要展开带公共绑定的模块，先解除绑定以保持来源明确。

`bundled_modules` 声明独立顶层实现包。运行前保存全部源码与依赖快照；入口代码、实现文件哈希、环境版本共同标识本次实现。代码页可浏览入口、内部函数和实现文件，历史运行读取冻结源码。

组件网络使用 `view="network"` 和 `graph` 参数驱动图形编辑、形状检查及实际PyTorch执行。图表使用 `view="chart"`，统计口径与样式分别保存。GUI和Agent共享这些定义和服务，自定义函数发布前必须检查语法和接口差异，发布记录保留来源。

完整操作、边界和示例见 [模块化研究使用与扩展](workflows/模块化研究使用与扩展.md)。
