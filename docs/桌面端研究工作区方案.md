## 1. 背景与目标

上一阶段已完成：Tauri 2 无边框桌面壳（窗口/托盘/文件对话框/拖放/后端进程管理/优雅退出）、
中英文完整切换、Research Studio（研究路径画布 + 结果底栏 + 成果中心）与 Agent（AI 研究室）的可用版本。

但两者目前是**两个独立页面**，成果只能看不能持续操作，桌面端的关窗/任务/恢复语义也没有完全定清。
本方案把它们连成一个连贯的研究工作区，并对桌面行为定规则。

目标（按优先级）：

1. **关窗、退出、停任务三者语义清晰且一致**，不丢任务、不误杀研究。
2. **研究工作区可布局、可恢复**：中央路径 + 右侧 Agent + 底部结果，三态辅助区、记住习惯、重启还原。
3. **成果可阅读、可固定、可对比、可继续操作**，最新结果与选定结果分开。
4. **Agent 的上下文可见可控**，任务状态与产物状态一致，长任务可离开页面继续。

非目标（本方案不做）：独立成果窗口、系统通知中心、多窗口协同、团队协作功能扩展、
Python sidecar、更新发布链路。

## 3. 设计原则

1. **状态真实**：Agent 说“完成”必须有 run/artifact 证据；对话状态、运行状态、成果状态三者可互相追溯。
2. **任务优先**：关闭窗口默认不影响任务；退出应用需要显式确认；停止任务是独立动作。
3. **可恢复**：窗口、布局、研究、草稿、未完成任务都能在重开后恢复；恢复失败要说明原因。
4. **安静**：默认只显示必要辅助区；三态（紧凑/展开/专注）由用户习惯驱动，不堆功能入口。
5. **本地优先**：本地模式（本机项目）先做完整能力；账号模式可降级（无“打开文件夹”等本机动作），不阻塞主路径。
6. **渐进兼容**：保留现有路由（`#/flow`、`#/lab`、`#/settings/local`）与组件，不推倒重来；改动以“加一层壳 + 状态”为主。

## 4. 阶段一：关窗语义（工作量 2–3 人日）

### 4.1 术语与规则

| 动作 | 含义 | 对任务的影响 | 入口 |
|---|---|---|---|
| **关闭窗口** | 隐藏到托盘，桌面进程与后端继续 | 无影响，继续运行 | 标题栏 ×、Alt+F4 |
| **退出应用** | 停止后端并退出进程 | 有任务时默认阻止，给出处理选项 | 托盘「退出 QuantLab」、设置里的“退出” |
| **停止任务** | 取消某个 run | 只影响该任务 | 运行横幅 / 任务与资源页 |

补充规则：

- 关闭窗口的行为由项目偏好决定：`ask`（每次询问）/ `background`（隐藏）/ `exit`（尝试退出）。默认 `ask`。
- 有任务时选择“退出”，不允许静默杀进程，必须出现三个选项：
  **隐藏到托盘继续**（默认）/ **完成后自动退出** / **取消**。
- “完成后自动退出”是会话级意图（`pending_quit`），不写入项目偏好；重启/取消后清空。
- 停止任务仍走现有 `POST /api/runs/{id}/commands {"command":"cancel"}`，不在关窗流程里自动触发。
- 系统关机/注销（Windows `WM_QUERYENDSESSION`）：允许系统退出，尽力调用 shutdown，不阻塞关机；下次启动按“异常退出恢复”处理。

### 4.2 状态机

```
             ┌─────────────── 关闭窗口（asks/background）──────────────┐
             ▼                                                          │
 [运行中] ──关闭窗口(exit)──▶ [退出确认] ──隐藏──▶ [托盘后台] ──关闭窗口──▶ [运行中]
                                │  │
                                │  └─完成后自动退出──▶ [等待任务] ──任务清空──▶ [shutdown → 退出]
                                └─取消──▶ [运行中]
 [无任务] ──关闭窗口(exit)/托盘退出──▶ [shutdown → 退出]
```

### 4.3 交互与文案

- 退出确认对话框标题：**还有 N 个任务在运行**。
- 正文列出前 3 个任务（名称 / 开始时间 / 当前步骤），并说明“关窗后任务会继续，退出会中断”。
- 按钮：`隐藏到托盘`（默认）、`完成后退出`、`取消`。
- 选择“完成后退出”后：托盘提示改为 `QuantLab · 等待 N 个任务完成后退出`；托盘菜单出现“取消退出”；任务清空后自动 shutdown + 退出。
- 设置 → 本地项目 → 关窗行为文案统一为：`关闭窗口` 与 `退出应用` 分开描述，避免“退出（有任务时阻止退出）”歧义。

### 4.4 后端契约改造

`POST /api/local/shutdown` 改为：

- 无任务：`200 {"stopping": true}`（保持兼容）。
- 有任务：`409 {"code": "tasks_running", "detail": "有未完成任务…", "tasks": [{"id","title","started_at","step"}]}`。

保留旧字段 `detail`（字符串）供旧 pywebview 启动器使用；新增 `tasks` 供 Tauri 展示。
`GET /api/local/tasks` 已有 runs/conversations，用于轮询；补充 `active_count` 便于托盘与轮询判断。

### 4.5 Tauri 实现要点

- `quit(app)` 拆成 `request_quit`（处理 409）与 `finish_quit`（shutdown + kill child + exit）。
- `Backend` 状态增加 `pending_quit: AtomicBool`。
- 选择“完成后退出”后启动一个轮询任务：每 5s 调 `/api/local/tasks`；为 0 时 `finish_quit`；失败退化为提示用户。
- 托盘菜单项动态：`退出 QuantLab` ↔ `等待任务完成后退出…` + `取消退出`。
- 窗口状态（大小/位置/最大化）随阶段二一起做：落盘 `%APPDATA%\com.quantlab.desktop\window.json`，启动时校验在屏幕范围内再恢复。

### 4.6 边界与风险

- 后端崩溃/无响应：shutdown 超时（8s）后提示“无法确认任务状态”，让用户选“强制退出”或“取消”，不默认强杀。
- 多实例：退出只影响当前实例与其后端（同项目复用同一后端时，另一个实例会收到服务已停止，需提示“服务已被另一个窗口停止”）。
- 更新安装（未来）：安装前必须复用“退出应用”流程；如果用户选择“完成后退出”，更新在退出后安装。本阶段只预留接口。

### 4.7 验收标准

1. 无任务：关闭窗口按三种偏好表现正确；托盘退出时后端停止、进程退出、日志有 `quit`。
2. 有任务：三种偏好下都不会丢任务；退出时出现三选项；选“完成后退出”后任务跑完自动退出；点“取消”任务继续。
3. `curl -X POST /api/local/shutdown` 在有任务时返回 409 且包含任务列表；无任务返回 200。
4. 强杀/崩溃后重启：出现“上次未正常退出”提示（配合阶段二恢复），不误报任务成功。

## 5. 阶段二：工作区布局与恢复（工作量 5–7 人日）

### 5.1 目标布局

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶部：项目名 · 研究名 · 运行状态 · 最近结果 ↗ · 窗口控制                  │
├───────────────┬──────────────────────────────────────────┬───────────────┤
│ 左侧导航      │ 中央工作区                                 │ 右侧辅助区     │
│ 项目/近期研究 │ 模式：研究路径 | 实验与比较 | 研究成果      │ 检查器         │
│ 收藏          │ 画布 / 步骤视图 / 成果列表                 │ Agent         │
│ 可收起        │ 节点选中 → 检查器联动                      │ 上下文         │
│               ├──────────────────────────────────────────┤ 可调宽/三态    │
│               │ 底部结果区（输出/输入/日志，可折叠、可拖高）│               │
└───────────────┴──────────────────────────────────────────┴───────────────┘
```

映射到现有实现：

- **左侧**：现有 `.wf-library`（230px）保留；在它上方增加“项目 / 近期研究 / 收藏”入口
  （近期研究来自 `/api/workflows`，收藏复用现有 favorite 机制）。
- **中央**：现有画布 + 步骤视图；顶部模式切换沿用 `path / experiments / artifacts`。
- **右侧**：现有 `.wf-inspector`（304px）改造成 **PanelHost**，三个页签：`检查器`（现有节点属性）
  / `Agent`（嵌入对话，阶段四完善上下文） / `上下文`（引用与 token 预算）；整列可调宽 280–420px。
- **底部**：现有 `ResultDock` 保留；增加“专注阅读”展开，默认折叠，高度持久化。
- **顶部**：现有 sticky toolbar 保留；把“最近一次结果 ↗”固定在最右，并新增运行状态胶囊。

### 5.2 三态与响应式

右侧辅助区三态：`compact`（只显示页签图标 + 当前任务摘要，默认）/ `expanded`（完整内容）/
`focus`（隐藏左右辅助区，中央内容最大化；Esc 退出）。

| 窗口宽度 | 默认 | 规则 |
|---|---|---|
| ≥ 1440px | 左 230 + 右 340，底栏可展开 | 可同时展开结果底栏 |
| 1100–1440px | 右侧 compact，底栏默认折叠 | 同一时间只允许一个辅助区展开 |
| < 1100px | 右侧改为抽屉，底部结果全屏覆盖 | 只保留中央工作区 |
| < 760px | 单列 | 沿用现有移动端样式 |

三态、宽度、底栏高度、上次模式写入 UI 状态（见 5.5），首次使用按窗口宽度给默认值。

### 5.3 Agent 嵌入方式

- 抽出现有 `StrategyLab` 的对话渲染 + Composer + 侧卡（`components/chat/*`、`apiLab.ts`）
  为可复用 `AgentPanel`，接受 `context` 与 `onNavigate`，不改变 Agent 后端协议。
- 工作区右侧默认渲染 `AgentPanel`（compact 时只显示最新一条消息 + 输入框）。
- `#/lab` 保留为 **Agent 专注模式**（全页对话），两处共享同一份 project/session 状态与流式连接。
- 从成果“继续修改”跳转时：`AgentPanel` 打开对应对话并附带成果引用（阶段四）。

### 5.4 恢复语义

| 状态 | 存储 | 恢复时机 | 失败处理 |
|---|---|---|---|
| 窗口大小/位置/最大化 | Tauri：`window.json` | 启动创建窗口前 | 超出屏幕 → 回默认居中 |
| 上次项目目录 | Tauri：`desktop.json`（已有） | 启动 | 目录不存在 → 项目选择器 |
| 上次工作流/研究 | 后端项目偏好 `desktop-preferences.json`：`last_workflow_id` | 启动进入家庭页/最近研究 | 不存在 → 最近研究列表 |
| 工作区模式/三态/宽度/底栏 | `localStorage`（按项目+工作流命名空间） | 进入工作区 | 解析失败 → 默认值 |
| 画布视口/选中节点/滚动位置 | `localStorage`（节流写入） | 重新打开该工作流 | 忽略越界值 |
| 未保存草稿 | `localStorage`（debounce 800ms，含 `revision` 指纹） | 打开时比对后端 revision | 冲突 → 横幅“已恢复草稿，可合并/丢弃” |
| 未完成任务 | 后端 run 状态 + 客户端 run_id | 启动/切回 | 提示“任务已结束/仍在运行” |

明确**不恢复**：弹窗、临时搜索词、一次性预览（可接受）。

### 5.5 客户端状态模型

```ts
// localStorage: qa.ws.state.v1（按 workflow id / project 分键，避免互相覆盖）
type WorkspaceState = {
  workflowId: string;
  mode: 'path' | 'experiments' | 'artifacts';
  view: 'canvas' | 'steps';
  rightPanel: 'inspector' | 'agent' | 'context';
  rightState: 'compact' | 'expanded' | 'focus';
  rightWidth: number;          // 280–420
  dockOpen: boolean;
  dockHeight: number;          // 180–700
  selectedNodeId?: string;
  canvasViewport?: { x: number; y: number; zoom: number };
  scrollTop?: number;
  updatedAt: number;
}
```

写入：用户操作后 debounce 300ms；读取：组件挂载时同步读取（避免闪回默认布局）。
切换工作流时先 flush 当前状态，再加载目标状态。

### 5.7 验收标准

1. 重启应用后：窗口大小/位置、上次项目、上次工作流、模式、右侧页签/三态/宽度、底栏状态、画布视口全部恢复。
2. 三态切换与宽度拖拽不抖动；窗口缩到 1100px 以下时自动只保留一个辅助区。

5. 手机宽度（<760px）布局不回归，右侧变为抽屉。

## 6. 阶段三：成果专注阅读（工作量 4–6 人日）

### 6.1 成果模型

沿用内容寻址 artifact（`hash`），在**项目/工作区**维度新增 `artifact_pins`：

```ts
type ArtifactPin = {
  id: string;
  hash: string;              // 内容地址
  run_id: string;
  workflow_id: string;
  node_id: string;
  port: string;
  title: string;
  type: string;              // table / image / report / file / json …
  note?: string;             // 固定说明（可选）
  pinned_at: number;
  pinned_by: string;
  version_key: string;       // `${workflow_id}:${node_id}:${port}`
}
```

- **最新结果**：按 `created_at` 取该 `version_key` 的最近一次运行产物（现有 listing 已有）。
- **固定结果**：`artifact_pins` 记录；一个 `version_key` 可以固定多个历史版本。
- **版本**：同一 `version_key` 的不同 hash + run_id，按时间排序；UI 显示 `v1/v2/…` 或 `r12 / r13`。
- 固定记录**不随缓存清理删除**；删除需要显式操作（先只做“取消固定”，不做级联删除）。

### 6.2 交互

**成果列表（研究成果 tab）**
- 增加筛选：`最新` / `已固定` / `全部版本`；行上显示固定标记与版本序号。
- 选中后在右侧/下方预览；预览头部固定操作：`固定`、`专注阅读`、`下载`、`更多`。

**专注阅读（Focus Reader）**
- 从预览或列表进入；居中大图/大表/报告，右侧元数据栏（来源运行、节点、端口、revision、时间、数据源）。
- 图片：适应窗口/100%/缩放，可下载；表格：分页 + 导出 CSV（现有表格组件能力）。
- 动作：
  - `固定成果` / `取消固定`
  - `对比上一版本`（同 version_key 的前一个 hash；并排 A/B，元数据 diff）
  - `继续修改`（带引用打开 Agent，见阶段四）
  - `在文件夹中显示` / `用系统应用打开`（仅本地模式；Tauri 命令）
  - `下载`（已有 download 链接；文件类可多文件）
- 键盘：Esc 关闭、←/→ 切换版本、Cmd/Ctrl+P 固定。

### 6.3 API 与数据

新增（本地模式与账号模式都走同一套，账号模式仅缺少本机路径动作）：

- `GET /api/workflows/artifacts/pins?workflow_id=&version_key=&limit=`
- `POST /api/workflows/artifacts/pins`（body 同 ArtifactPin 输入）
- `DELETE /api/workflows/artifacts/pins/{id}`
- `GET /api/workflows/artifacts/{hash}/versions?version_key=`
  （返回同一 key 的历史，含当前是否固定）
- 本地模式：`GET /api/local/artifacts/{hash}/path` → `{path}`（校验在项目 files 目录内），
  供 Tauri `native_reveal_path` / `native_open_path` 使用；账号模式返回 404，前端隐藏入口。
- 存储：项目 store 新集合 `artifact_pins`；清理逻辑（`/api/local/cache/clear`）跳过被固定 hash。

### 6.4 实施步骤

1. 后端 pins 集合与 4 个接口 + 单测（固定/取消/版本查询/清理保护）。
2. 前端 `ArtifactReader`（专注阅读）与 `ArtifactMeta` 组件；接入现有 `ArtifactPreview` 渲染器。
3. 成果列表筛选与版本序号；工作区顶部“固定成果”入口。
4. Tauri 本机动作：`native_reveal_path`、`native_open_path` + 权限。
5. “对比上一版本”最小实现（并排 + 元数据 diff）。

### 6.5 验收标准

1. 生成图表/表格/报告后，可固定；固定在重启、重开项目、清理缓存后仍存在。
2. 同一节点多次运行后，可看到版本列表、固定任意版本、对比上一版本。
3. 专注阅读可放大、下载、打开文件夹（本地模式）；Esc/箭头键盘操作正常。
4. 最新结果与固定结果同时存在时，顶部“最近结果”与“已固定”入口不混淆。

## 7. 阶段四：Agent 上下文可见性（工作量 4–5 人日）

### 7.1 上下文对象

在现有 pins / ContextView 基础上增加**研究工作区上下文**：

```ts
type WorkspaceContext = {
  workflow_id?: string;
  workflow_title?: string;
  run_id?: string;              // 当前/最近运行
  selected_node_id?: string;
  selected_port?: string;
  artifact_pins: { id: string; hash: string; title: string; type: string }[]; // 引用成果
  mode: 'path' | 'experiments' | 'artifacts';
}
```

- 客户端在每次发消息时带上 context（或落在会话 `pins` 里，二选一，建议显式随消息发送，可追踪）。
- Agent 后端把它写入 message metadata，并作为工具调用的可见范围（不自动读全文，按需读取）。
- `ContextView` 增加 `workspace` 段落，展示固定上下文占用的 token。

### 7.2 上下文栏（Agent 面板顶部）

一行紧凑展示：

> 当前研究：**动量轮动 r12** · 已选节点：**因子评价** · 引用成果：3

- 点击研究名 → 回到工作区定位；点击节点 → 画布选中并滚动；引用成果 chip 可单独移除。
- “引用成果”来自固定成果或阅读器里的“引用到对话”。
- 下方可折叠“上下文详情”（对齐现有 `ContextView` 面板）：固定项 / 可压缩项 / token 预算。

### 7.3 任务状态语义

统一状态映射，避免“对话说完成了、成果还没出现”：

| 状态 | 判定 | UI 文案 | 可执行动作 |
|---|---|---|---|
| 等待输入 | Agent 需要用户确认/补充 | 等待你确认 | 回答 / 取消 |
| 排队中 | run QUEUED/PENDING | 排队中（第 N 位） | 取消 |
| 生成中 | Agent 正在调用工具或 run RUNNING | 正在生成…（当前步骤） | 查看进度 / 取消 |
| 已生成 | run COMPLETED 且至少 1 个 artifact/证据 | 已生成 3 项成果 | 查看成果 / 固定 / 继续修改 |
| 执行失败 | run FAILED 或工具错误 | 执行失败：原因 | 重试 / 查看日志 |

规则：**“已生成”必须以 run/artifact 存在为条件**；只有文字回复时显示“已回复”，不显示“已完成”。
长任务在消息上显示 run_id 与进度条；离开页面后状态由全局运行横幅继续展示。

### 7.4 长任务与恢复

- 复用现有 run 机制：Agent 触发的研究在后台继续；消息记录 run_id。
- 用户离开工作区再回来：`AgentPanel` 重新挂载后按 run_id 拉取状态与产物，恢复“生成中/已生成”展示。
- 关窗到托盘任务继续（阶段一保证）；退出时有任务会阻止（阶段一）。
- 任务完成/失败：先做**应用内**提示（运行横幅 + toast）；系统通知留到独立排期。

### 7.5 实施步骤

1. 后端：消息 metadata 支持 `workspace_context`；`ContextView` 增加 workspace 段；pins 支持 `kind:'artifact'`。
2. 前端：`AgentContextBar` 组件 + 移除引用 + 点击定位。
3. 状态映射与“已生成/已回复”区分；消息内 run 状态订阅（复用现有 SSE/轮询）。
4. 引用成果 → Agent pins 的映射；“继续修改”从阅读器带入引用并预填提示词。
5. 离开/返回恢复（run_id + 会话状态）。

### 7.6 验收标准

1. 上下文栏始终显示当前研究/选中节点/引用数量；移除引用后下一轮不再携带。
2. 五种状态与后端 run 状态一致；不存在“显示完成但没有产物”的情况。
3. 从成果阅读器“继续修改”进入 Agent，引用自动出现且对话能定位到该成果。
4. 长任务期间切换页面/最小化到托盘，回来后状态与产物正确恢复。

### 风险与对策

- **AgentPanel 抽取影响现有 `#/lab`**：先做只读嵌入，保持原页面不变；回归测试覆盖 lab 主路径。
- **三栏 + 底栏同时展开导致中央空间不足**：用 5.2 的宽度阈值与“只允许一个辅助区”规则，并提供专注模式。
- **状态恢复冲突（草稿 vs 远端 revision）**：沿用已有 `remote` 冲突提示，默认保留草稿、显式合并。
- **固定成果与清理策略冲突**：固定记录与 blob 不参与缓存清理；先只做保护，不做跨项目迁移。
- **账号模式差异**：本机路径动作仅本地模式；固定/版本/上下文在账号模式同样可用（存储在工作区 store）。

## 9. 暂不纳入（独立排期）

- **Python sidecar**：PyInstaller onedir、冻结后的 `sys.executable` 子进程修正、资源收集、干净机验收。

- **系统通知**：Windows toast 通知（任务完成/失败、更新可用）。
- **独立成果窗口 / 多窗口协同 / 单实例插件**。

## 10. 需要确认的决策点

1. **Agent 默认形态**：右侧默认展开（340px）还是 compact（只显示最新消息 + 输入）？建议先 compact，用户展开后记住。
2. **底部结果区默认**：默认折叠 / 运行结束后自动展开？建议“运行结束自动展开一次，之后记住用户选择”。
3. **固定成果作用域**：按项目（跨研究可查）还是按研究（只在当前研究可见）？建议项目级，列表默认筛当前研究。
4. **账号模式优先级**：本方案按“本地模式先完整、账号模式降级兼容”推进；如果账号模式也要完整，需要加 2–3 天。
5. **“完成后退出”默认选项**：有任务时默认聚焦“隐藏到托盘”还是“完成后退出”？建议前者更安全。
