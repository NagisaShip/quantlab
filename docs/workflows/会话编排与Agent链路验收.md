## 创建和修订

推荐新建时调用 `workflow_create(workflow=...)`，不需要先有 ID。兼容 `workflow_revise(workflow_id="", expected_revision=0, workflow=...)`。创建结果包含真实 `id`、`revision=1` 和 `created=true`。更新必须提供当前修订号；冲突不覆盖。未知 ID 携带非零修订号不会误创建。

平台工具和研究室平台桥接均将“缺失”定义为未传键或 None。0、False、空字符串先作为值传给对应业务校验，不再统一按真值拒绝。失败工具结果在会话中显示失败，不再显示成功耗时。

历史版本行的内部存储键不再泄入公开工作流 ID。读取修订1仍返回原始工作流 ID，运行证据绑定相应工作流和冻结修订；跨工作区、跨工作流及无关子运行访问会拒绝。

## 结构、分页和错误恢复

- `workflow_help(topic="workflow"|"network"|"artifacts")` 提供准确示例。
- `workflow_catalog(section="cards"|"workflows", cursor="", limit=6, query="")` 返回 `total`、`next_cursor`、`truncated`，工作流条目包含 revision。卡片目录只返回紧凑接口，避免源码挤占目录预算。
- `workflow_sources(kind,version)` 先列入口与实现文件。指定 `file_path="NODE.py"` 或实际实现路径后，用 offset/limit 分段读源码，按 next_offset 继续。
- 超过对话文本预算的工具结果返回可解析 JSON 和显式截断、恢复方法，保留新建 ID、实验运行 ID 等后续操作必需字段；不再从 JSON 中间硬切。
- 工作流连接以 `source/source_port/target/target_port` 为标准，兼容 `from:{node,port},to:{node,port}`，保存时规范化。两种写法冲突会拒绝。

网络组件图使用 nodes 和 output。输入节点例：`{id:"in",type:"Input",shape:[8]}`；线性层例：`{id:"out",type:"Linear",inputs:["in"],out_features:1}`。shape 不含 batch。支持明确的 edges 连接，以及 input/dense 别名；规范化后的图直接用于代码生成和模型执行。报错给出节点类型、收到的键及允许字段，不猜测 dim 等字段的含义。

`artifact_hash` 来自运行报告 `nodes[节点].outputs[端口].hash`，与资产 sha256、代码哈希、文件校验值属于不同用途。`workflow_artifact` 可分页读取真实工件。`workflow_chart_preview(config=..., data=[...])` 允许最多5000行显式表格，无须先运行；与 artifact_hash 二选一。错误提示包含合法哈希来源。

## 会话中的轻量编排图

AI研究室工具消息和“问 AI”侧栏共用轻量组件，不加载完整画布编辑器。展示保存修订、卡片连线、节点状态、参数、输出工件及模块内部证据。显示来自后端保存状态和真实运行报告的结构化数据，不解析模型正文生成虚构运行状态。

未运行显示“未运行”；有 run_id 时轮询实际运行，终态停止轮询，错误可手动刷新。卡片支持键盘选择；超过8张默认展示部分并明确标记，允许展开。详情中列出实际端口连接。输出预览限制前20行，完整数据入口在原画布。

“在完整画布打开”在新标签定位到同一工作流、冻结修订、运行和选中节点，保留原会话与原标签草稿。跨工作区不展示或读取原工作区工件。对话内预览是只读的，不额外提供隐式保存、覆盖或运行按钮。

新增测试通过实际研究室平台桥接执行：目录、读取源码、发布不可覆盖版本、expected_revision=0创建、字段/唯一键检查、运行、节点工件、图表统计预览、参数网格提交及结果比较。另覆盖不合法网络输入、图结构规范化与实际参数量、哈希用途、截断后仍可解析的JSON、修订冲突和工作区隔离。构造数据的均值只用于验证计算与证据读取。

资产定义快照仍然需要实际行情或数据表输入；资产历史摘要和定义 sha256 不会自动变成数据源。已发布的用户函数版本不会被本轮修复覆盖。
