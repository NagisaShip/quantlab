# 模块化研究工作台：使用与扩展

## 从完整研究开始

进入“研究工作流”，默认浏览完整研究模块。新建菜单提供数据整理、策略与净值、模型训练及冻结测试、组件神经网络四种起点，原有模板仍保留。

1. 从 CSV 数据源导入文件，确认标识、时间与数值字段。证券代码前导零保留；金融函数只转换明确使用的数值字段。
2. 在完整模块上填写少量公开参数。参数显示中文名称、内部键、默认或手动来源、范围；模型参数根据算法显示。
3. 需要调整时点击“展开为可编辑卡片”，每次展开一层。尚未填完参数的草稿也可以展开，执行自检仍严格要求完整参数和输入。
4. 调整后，在“封装为我的模板”选择卡片，命名并勾选公开参数。边界端口自动生成；未填写的必填参数自动公开，其他未公开参数保留当前值。
5. 先自检，再执行到某张卡片或运行全链路。修改过的画布与上次运行证据明确区分。

公开参数使用 `subflow.parameters` 映射到明确的内部节点参数，可将一个公开参数映射到多个内部函数。参数来自输入绑定时，执行阶段先解析实际值；为避免悄悄改变来源，带公共运行时绑定的模块须先解除绑定才能展开。

画布、选择、运行证据和视口在进入独立代码页后保留。草稿在当前浏览器会话中保存，并有内存回退；这不等于已保存到服务器。跨用户编辑仍检查工作流修订号。

## 基础函数与已有研究

基础函数按数据整理、数据质量、数据变换、时间与样本、统计计量、因子研究、模型、策略、组合风险、图表及神经网络分类。包括重命名、去重、类型转换、排序、筛选、连接、聚合、长表、质量检查、训练期拟合/应用变换器、滞后、普通/清除标签重叠的时间切分、描述统计、相关、IID Bootstrap、OLS/实体固定效应、收益率、滚动因子、截面排名、行业去均值、IC、分组收益、信号、延迟回测、波动倒数权重、回撤及模型训练预测评价。

原有因子、组合、执行专业页和工作流调用 `quantlab_research.engines` 中同一份引擎；原导入路径保留兼容入口。因子表达式、组合配置和执行配置可从当前工作区已有资产生成冻结定义模块。

**原生策略与原生模型资产目前接入为定义快照**，保留原协议与专业页入口；它们不会被自动转换为工作流的基础阈值策略或 sklearn 模型。新增工作流完整策略模块、模型模块可独立执行；需要运行既有原生资产完整生命周期时仍使用对应专业页或编写明确适配器。快照的资产 ID、内容和哈希保留在卡片定义中，之后修改原资产不会改写该快照。

## 图表工作台

支持折线、柱状、面积、散点、直方、箱线、热力、关系网络、蜡烛图。结果中的表格可直接“由此生成图表”，自动接入图表卡片。图表参数分为统计口径和样式；预览读取已冻结的输入工件，不重新训练上游。

正式运行保存绘图数据、口径、配置、PNG、SVG。工作台支持配置与绘图数据 JSON 下载及图像下载。只修改图表参数时，上游函数复用缓存；组合模块会核验内部缓存，保留子运行证据。

预览最多5000行、分组最多40组，网络最多200节点、蜡烛最多300根。超限须先显式筛选或聚合，不自动抽样。K线推算盘口、基础延迟回测等假设随各自报告保留。

## 神经网络组件

Input、Linear、ReLU、GELU、Sigmoid、Tanh、Dropout、LayerNorm、Flatten、Add、Concat、GRU、Identity 可通过连线构造实际网络。检查会显示不含 batch 的输入输出形状和参数量，拒绝循环、断路、残差形状不一致等错误；实际模型参数量再次核验。

图定义直接生成 PyTorch 执行模型。完整基础训练器支持单输入表格二分类、验证损失早停和冻结预测，记录训练曲线、权重名称、形状和摘要。GRU 组件支持序列图，序列/多输入训练须编写自定义训练函数。基础执行器上限一千万参数；不声称能将任意 Python 网络反向编辑成标准组件图。

组件位置存入卡片 `ui.network_layout`；计算图和训练参数分别保存，单独拖动布局不改变计算参数。

## 独立代码页与自定义规范

点击卡片“代码”打开独立页面，复用策略编辑器的高亮、行号、缩进、快捷键及差异视图。左侧列出入口、内部函数定义和真实实现文件；内部函数可继续打开并复制自定义。实现包文件只读，避免修改公共库意外影响其他模块；自定义入口可以自由组合、调用或替换其函数。

每张卡片是 UTF-8 Python 文件，包含唯一字面量 `NODE` 和 `execute(ctx, inputs, params)`，例如：

```python
NODE = {
    "kind": "user.filter_positive", "version": "1", "title": "保留正值",
    "level": "function", "category": "自定义处理",
    "inputs": {"data": {"type": "table"}},
    "outputs": {"data": {"type": "table", "role_from": "data"}},
    "parameters": {"type": "object", "properties": {
        "field": {"type": "string", "default": "value", "title": "数值字段"}
    }, "additionalProperties": False},
    "requirements": []
}

def execute(ctx, inputs, params):
    field = params["field"]
    return {"data": [dict(row) for row in inputs["data"] if float(row[field]) > 0]}
```

端口支持 `type`、`role`、`forbid_roles`、`schema` 和 `semantics`。`semantics` 可明确单位、时区、实体键、模型后端等，目标端声明的具体语义必须匹配；未声明不代表系统自动推断。`role_from` 保留输入的训练/验证/测试用途；连接类函数可使用输入名数组，测试/验证用途不会被重标为训练。

参数支持 type、properties、required、additionalProperties、enum、minimum/maximum、minLength/maxLength、items、minItems/maxItems、default；`title`/`description` 用于人类说明，`visible_when` 用于条件展示，`widget: "json"` 用于任意 JSON 值。输入绑定支持对象键和数组下标路径。

通过 `ctx.seed`、`ctx.log`、`ctx.file`、`ctx.work`、`ctx.save_file` 访问种子、日志和显式资源。返回值严格对应声明端口，使用可 JSON 序列化内容，文件以包含哈希的工件引用返回。不原地修改输入，影响结果的内容须进入参数、代码、文件或依赖。

发布前检查语法和接口差异，同 kind/version 不可覆盖。入口版本与实现文件哈希共同标识运行实现，任务开始时冻结完整代码和源码包；查看历史运行代码读取冻结内容。

## 实验与 Agent

多种子实验保留；参数网格最多4轴、8组。滚动窗口显式指定切分卡片的训练和验证截止，当前是扩展训练区间。先预览，再按冻结修订提交；原画布不被实验参数覆盖。配额导致部分提交时返回已提交 ID 和错误，避免丢失记录或误称全部成功。对比保留失败/未完成状态，不自动挑选最优模型，支持下载对比数据。

GUI 和 Agent 共用注册表、服务、自检、运行器、源码和实验记录。Agent 工具包含目录、工作流检查/修改/执行、源码文件浏览、自定义函数预览/发布、资产快照、图表口径预览、网络检查、实验计划/提交/比较。发布和修改记录 Agent 来源。页面“问 AI”附带当前工作流、选中卡片、修订、未保存状态和代码，实际运行仍采用已保存修订。

## 环境与离线导出

研究依赖安装到实际服务/Worker 使用的 Python 环境：

```text
python -m pip install -e ".[research]"
python -m pip install -e ".[research,neural]"
```

第二条用于组件网络训练，包含 PyTorch。目录浏览和网络结构检查不要求导入训练库；执行前自检列出具体缺失依赖及版本约束。当前运行器使用启动平台的 Python，未实现每张卡片自动切换解释器。

独立运行包包含准确卡片版本、递归内部定义、源码包、输入文件、运行器、全部依赖 wheel 与带哈希的锁文件。Windows 的 setup.bat 使用包内 wheel 离线安装；不需要平台账号、API 或数据库。Python 主次版本、操作系统和架构须与包清单一致，包不附带解释器。

离线验证已在全新环境中完成：仅从14个随包 wheel 安装依赖，在未安装 QuantLab 的解释器中运行“CSV→完整策略模块→图表”，全部节点完成并通过内容哈希校验。该验收使用明确构造的示例数据，只验证软件运行与导出完整性。

## 直连行情数据源（source.market）

研究工作流的「数据源」分类新增「直连行情数据源」卡片，不必先把行情导入文件：

- 参数：标的（`BTC/USDT` 或 `BTCUSDT`）、周期（1m / 5m / 15m / 30m / 1h / 4h / 1d）、K 线根数（50–5000，默认 1500）、交易所（auto / binance / okx / bybit）、取数方式（auto / exchange / synthetic）。
- 行为：只取已收盘 bar；`auto` 先试真实交易所，取不到时按平台合成行情开关决定是否显式回退并在来源中标注；`exchange` 只接受真实行情；全部失败会把交易所返回的原因写进节点错误，不伪造数据。
- 输出：`data` 表（time / open_time / close_time / open / high / low / close / volume / source）与 `source` 报告（交易所、实际来源、覆盖区间、抓取时间、缺口/重复/未收盘、缓存滞后警告）。数据在本次运行内冻结为不可变工件；该卡片声明 `cache=false`，同样参数再次运行会重新抓取，不会把旧行情当成本次数据。
- 与导出：卡片声明 `capabilities.network`，**直接导出工作流定义**会被拒绝（提示先运行一次）。运行成功后从这次运行导出「冻结运行」包时，导出器会把这个节点的行情数据写成 `frozen-market-*.csv`（同时保留原始来源报告 `frozen-market-*.json`），把节点替换成「CSV数据源」再打包，因此冻结包仍是完整离线包；`manifest.json` 的 `frozen_sources` 记录来源节点、文件、行数与哈希。若下游还连接了 `source` 来源报告端口，则明确拒绝（避免悄悄丢数据）。
- 该卡片只在平台运行时于工作进程内执行；独立运行包使用冻结后的 CSV，不会去连交易所。
- Agent 入口：`workflow_help(topic='workflow')` 的 `market_example` 给出可直接创建的节点；`workflow_files` 仍只用于查询已导入文件。

## 界面与布局（2026-10-21 优化）

工作流页改为“页头操作区 + 自适应编辑区”的结构：页头只保留打开工作流、从模板新建、画布/步骤切换、撤销/重做、保存、全链路自检和主行动“运行研究”；导出独立运行包、导入工作流、导出工作流 JSON、执行环境与本地文件收进“更多”菜单（执行环境现在跳转设置 → 本机 → 本地项目）。标题行用徽标显示草稿/修订号、卡片数、连接数和运行状态。

编辑区按视口高度自适应，桌面为“模块库 + 画布 + 检查器”三栏，模块库与检查器可折叠成窄条；窄屏依次变为两栏和单列，不出现横向溢出。实验网格、多种子实验、历史实验/版本、运行前检查、分支状态默认收起为分区卡片，位于画布下方；点击卡片或连线会展开检查器，空画布提供浏览模块库和载入内置模板的快捷入口。所有原有按钮语义与可访问名称保留。
