## 0. 现在有哪些扩展位

| 扩展位 | 载体 | 要不要改代码 | 主要落点 |
| --- | --- | --- | --- |
| 策略 | 一个 `.py` 文件（策略 SDK） | 不用 | 界面「策略」页或 `POST /api/studio/strategies` |
| 自定义数据（自己的时间序列） | CSV：`ts,value[,available_at]` | 不用 | [API 参考 · 信息源](API参考.md)、`POST /api/datahub/import` |
| 内置数据连接器（加密行情、宏观、链上…） | `CONNECTORS` 规格 + 抓取函数 | 要 | `research/datahub.py` |
| 行情来源 / 交易所 | 适配器类 | 要 | `exchanges/base.py`、`exchanges/__init__.py` |
| 前端内容块 | `ql:<类型>` 结构化 JSON | 要 | `agents/blocks_protocol.py` + `web/src/components/blocks/protocol.ts` |
| 工作区能力开关 | `FEATURES` 注册表 | 要 | `platform/features.py` |
| 平台工具（Agent 可调用的工具） | 工具函数 + 提示词 | 要 | `api/routes_*.py` + `agents/` |

一条经验规则：**能在界面上完成的扩展优先走界面**（策略文件、CSV 导入、模型服务登记），
只有新增「外部数据源 / 交易所 / 新渲染类型」才需要改代码。

## 1. HTTP API 约定（第三方接入先读）

机器可读规范：[`docs/openapi.json`](openapi.json)；可交互调试：运行实例的 `/docs`。
中文端点表由 `scripts/gen_api_doc.py` 从 FastAPI 的 OpenAPI 规范生成（`docs/API参考.md`），
CI 会校验两者一致，所以**不要手改 `API参考.md`**，改完路由后跑一次生成脚本即可。

### 认证与请求头

| 项 | 规则 |
| --- | --- |
| 会话 | Cookie `qa_session`，或 `Authorization: Bearer <token>`（`api/middleware.py:123`） |
| 写操作 | 用 Cookie 认证时必须带 `X-Requested-With`（跨站表单防护，`api/middleware.py:132`）；用 Bearer 不强制 |
| 工作区 | 请求上下文决定工作区，跨工作区数据不会互相可见 |
| 只读审阅者 | 带审阅者角色的账号只能读，写操作返回 403（`api/middleware.py:161`） |

### 错误契约

所有错误同一形状（`platform/errors.py:1`）：

```json
{ "code": "INVALID_PARAMETER", "message": "人能读懂的中文说明", "trace_id": "…", "details": {} }
```

`code` 是稳定枚举（`ErrorCode`），客户端应按它分支，不要解析 `message`。常见值：
`UNAUTHENTICATED`、`PERMISSION_DENIED`、`NOT_FOUND`、`INVALID_PARAMETER`、`QUOTA_EXHAUSTED`、
`DATA_INCOMPLETE`、`MARKET_DATA_STALE`、`UNSUPPORTED_CAPABILITY`。

### 分页与弃用

- 列表接口要么给 `limit`，要么给游标（如 `GET /api/runs?limit=&cursor=` 返回 `has_more` 与 `next_cursor`）。
- 被替换的旧接口会带 `Deprecation: true` 响应头，例如 `GET /api/strategies`（`api/routes_strategies.py:20`）。

## 2. 策略插件（SDK）

一个策略 = 一个 `.py` 文件，同一份文件在**回测 / 实时模拟 / 实盘对照**三种模式下都不用改。

### 2.1 必须写什么

- `initialize(ctx)`：注册定时任务（`run_daily` / `run_weekly` / `run_monthly` / `run_timer`）、
  设置基准与成本（`set_benchmark` / `set_order_cost` / `set_slippage`）。
- 至少一个回调：`handle_data(ctx)`、`on_bar(ctx)`、`on_fill(ctx)`、`on_order_filled(ctx)`、
  `before_trading_start(ctx)`、`after_trading_end(ctx)`。
- 用 `order_target_percent(symbol, w)` / `order_target_value` / `order_target` 表达**目标仓位**，
  而不是自己算手数；撮合、手续费、滑点、资金费与强平由账本处理。

### 2.2 最小示例

```python
# my_strategy.py —— 直接把整份文件贴进「策略」页，或 POST /api/studio/strategies
def initialize(ctx):
    set_benchmark("BTC/USDT")
    g.fast, g.slow = 12, 48
    run_daily(rebalance, time="close")

def rebalance(ctx):
    s = ctx.securities[0]
    fast = ctx.indicators.ema(s, g.fast)   # 平台预计算，逐 bar O(1)
    slow = ctx.indicators.ema(s, g.slow)
    order_target_percent(s, 0.8 if fast > slow else 0.0)
```

### 2.3 参数声明与调用

模块级变量写 `PARAMS`，或在 `initialize` 里用 `get_param("k", 默认值)` 读取；界面会自动生成参数表单。
完整可用 API 清单见 `src/quant_agent/sdk/__init__.py`（`__all__`，约 80 个名字）。

### 2.4 沙箱与静态检查

| 机制 | 说明 |
| --- | --- |
| 静态检查 | `check_source()`（`sdk/runner.py`）：禁止 `FORBIDDEN_NAMES` —— `place_order`、`cancel_order`、`withdraw`、`api_secret`、`private_key`、`requests`、`httpx`、`urllib`、`socket`、`subprocess`、`os.system` |
| 注入 | SDK 名字直接注入，不需要 `import`（`INJECTED`，`sdk/runner.py`） |
| 隔离执行 | 回测在受控运行时里跑；实时/实盘在隔离子进程里跑，拿不到交易所密钥（`platform/isolation.py`、`platform/sandbox_exec.py`） |

### 2.5 本地跑一遍

```python
from quant_agent.sdk import load_file, run_backtest

result = run_backtest(load_file("my_strategy.py"), {"BTC/USDT": bars})
print(result.metrics["total_return"])
```

### 2.6 验证

1. 界面「策略 → 新建」贴代码 → 保存时若命中禁用名会**直接报错**（这是预期行为）；
2. 跑一次回测，检查 `backtest/{id}` 页面里的数据来源、成本假设与体检项；
3. 用「AI 审稿」或人工检查交易次数、样本外与 2 倍成本表现，再决定是否批准上线。

## 3. 数据源插件

### 3.1 行情（K 线）来源

`MarketDataService.get_bars(symbol, timeframe, n, source=…)`（`data/service.py:356`）支持三种来源：

| `source` | 行为 |
| --- | --- |
| `auto`（默认） | 先试真实交易所行情，交易所不可达时**不会**偷偷用合成数据（`allow_synthetic` 默认关闭，`data/service.py:339`） |
| `exchange` | 只用真实行情；拿不到就报「未接入数据」 |
| `synthetic` | 只用教学合成数据（需要 `QAGENT_ALLOW_SYNTHETIC=1`），界面上会单独标注 |

页面里的「浏览器直连交易所」是另一条路径（`web/src/marketDirect.ts`）：浏览器直接向交易所 REST 取行情，
服务器连不上外网时也能看图，但**不写服务器缓存**，回测仍以服务器数据为准。

### 3.2 新增一个内置连接器（需要改代码）

三步，全部集中在 `src/quant_agent/research/datahub.py`：

1. **登记规格**：往 `CONNECTORS`（`datahub.py:75`）加一条
   `{"id", "name", "category", "needs_key", "fields", "scope", "note", "url"}`；
   字段名要进 `FIELD_SCOPE`（`datahub.py:35`），说明它是按标的还是按市场。
2. **实现抓取**：写一个返回 `list[(ts, available_at, value)]` 的方法。
   `available_at` 是**这条数据当时对外可见的时间**，因子按它做 as-of 对齐；宏观数据要留发布滞后
   （参考 `FRED_LAG_DAYS`，`datahub.py:56`）。
3. **接入分发**：在 `DataHub.sync()` 的分支链（`datahub.py:392` 起）里加一个 `elif connector == "你的 id":`，
   用 `run(field, symbol, source, fetcher)` 逐字段同步。单个字段失败只影响它自己。

需要密钥的连接器：把 `needs_key` 设为真，密钥从 `secrets_fn()["datahub:<id>"]` 读；
平台管理员在「行情与数据」页填写（`POST /api/datahub/keys`，仅部署管理员，`api/routes_datahub.py:215`）。

同步与自动补数：

```http
POST /api/datahub/sync      # {connector, symbols[], period, start, end, series, name, wait}
POST /api/datahub/auto      # {enabled, interval_hours} 让 worker 定期把已有数据集补到最新
GET  /api/datahub/datasets  # 已有数据集（字段 × 标的 × 来源）
GET  /api/datahub/datasets/{key}/series?limit=400
```

### 3.3 不改代码：上传自己的时间序列

```http
POST /api/datahub/import
{ "name": "my_signal", "symbol": "BTC/USDT", "lag_hours": 0,
  "text": "ts,value\n1700000000000,0.42\n1700003600000,0.51\n" }
```

导入后在因子里用 `x_<name>` 引用（`api/routes_datahub.py:201`，实现 `datahub.py:719`）。

### 3.4 新增一个交易所适配器（需要改代码）

1. 在 `exchanges/base.py` 的 `BaseAdapter` / `ExchangeAdapter` 上实现需要的方法
   （行情、标的、余额、下单意图 `OrderIntent`；不支持的能力抛 `UnsupportedFeature`）。
2. 在 `exchanges/__init__.py` 的 `public_adapter(exchange)` 里注册；`ccxt:<交易所>` 前缀已可直接转发到 `CcxtAdapter`
   （`exchanges/__init__.py:18`）。
3. 合约规格放 `exchanges/contracts.py`，能力边界同步登记到 `platform/features.py`（见第 5 节）。

### 3.5 验证

```bash
curl -s -X POST localhost:8000/api/datahub/sync -H 'content-type: application/json' \
  -H 'X-Requested-With: web' -b cookie.txt \
  -d '{"connector":"binance_futures","symbols":["BTC/USDT"],"period":"1h","wait":true}'
curl -s localhost:8000/api/datahub/datasets -b cookie.txt
```

返回里 `errors[]` 为空表示成功；界面路径是「行情与数据 → 信息源」。

## 4. 内容块插件（`ql:*`，前端渲染）

Agent 的回答、帖子与报告里可以放结构化内容块：

````text
```ql:chart
{"title": "净值", "kind": "line", "x": [1,2,3], "series": [{"name": "策略", "data": [1,1.2,1.5]}]}
```
````

协议在**前后端各有一份**，必须同时改：

| 侧 | 文件 | 要改什么 |
| --- | --- | --- |
| 后端 | `src/quant_agent/agents/blocks_protocol.py` | 类型清单 + 给模型的字段说明 |
| 前端 | `web/src/components/blocks/protocol.ts` | `BlockType`、`BLOCK_TYPES`、`BLOCK_LABEL` |
| 前端渲染 | `web/src/components/blocks/RichBlock.tsx` | 在分发处加一个 `case '你的类型'` |
| 样式 | `web/src/stylesBlocks.css` | 需要的类名 |

必备约束：

- 每个块都可以带 `source`（数据从哪来）与 `evidence`（`measured` 实测 / `inferred` 推断 / `external` 外部来源）——
  把推断和实测分开是这个平台的核心约定，新块不要省掉。
- JSON 解析失败时**不要抛异常**：`parseBlock()` 会返回 `{error, raw}`，界面会把原文显示出来并回报给 Agent。
- 渲染失败要调用 `useReportRenderError`（`web/src/components/blocks/renderErrors.ts`），
  这样对话里的错误会被收集并交回 Agent 自动修正。
- 内联 HTML / SVG 一律过 `sanitizeHtml()`（DOMPurify，`web/src/components/blocks/Html.tsx:50`），
  不要绕过它。

## 5. 能力开关（`platform/features.py`）

新功能只要涉及「市场 / 执行 / 研究」边界，就必须在 `FEATURES` 注册表里登记，写明
`default`、`label`、`implementation`（`ready` / `research` / `partial` / `not_implemented` / `blocked`）、
`group`、`note`。注册表是 API、界面、Agent 工具与文档的**唯一事实来源**：

- 没实现的能力**不允许**被工作区管理员打开（避免「界面能选、引擎跑不了」）；
- 当前能力矩阵可以直接读：`GET /api/capabilities`（`api/routes_capabilities.py:16`）。

## 6. 目前不支持的扩展方式

- **没有动态插件加载器**：不能像 VS Code 那样丢一个包进去就自动注册工具、路由或界面组件。
  新增路由/工具/块类型都要改上面列出的源码文件，并跟着发版。
- **没有出站 Webhook / 第三方 OAuth 应用**：平台对外是 HTTP API + 会话认证，不主动回调外部地址。
- **策略里不能联网**：`requests` / `httpx` / `socket` 等被静态检查拦下，这是隔离设计的一部分。
- **前端没有第三方组件沙箱**：`ql:*` 与内联 HTML 只能渲染白名单标签，不能注入脚本（DOMPurify 之后
  还会过一层 `safeHref` / `safeImageSrc`）。
- **数据连接器不能由用户在界面上新增**：界面只能填写已有连接器的密钥、或导入 CSV。

## 7. 提交前自检

```bash
python -m ruff check src tests scripts && python -m ruff format --check src tests scripts
python -m pytest -q                      # 后端
python scripts/gen_api_doc.py && git diff --exit-code -- docs/API参考.md docs/openapi.json
cd web && npm run build                  # 前端类型检查 + 构建
cd .. && npm run e2e:typecheck
npm run qa:mermaid                       # Mermaid 中文兼容自检
npm run i18n:check                       # 英文界面中文残留巡检
```

涉及界面文案时：中文原文是唯一真值，英文补进 `web/src/i18n/en.json`；
带变量的模板句补进 `web/src/i18n.en.ts` 的 `EN_PATTERNS`；抽取缺口的脚本是
`node web/scripts/i18n-extract.cjs`。
