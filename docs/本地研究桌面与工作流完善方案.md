# QuantLab 本地研究桌面与工作流完善方案

日期：2026-10-21。范围为平台能力，不涉及课程作业，不覆盖已发布函数版本，不执行 Git commit。

## 产品原则

共用同一研究核心、函数契约、运行器和证据体系，提供本地个人模式与账号协作模式。两种模式显式选择，不通过“自动跳过登录”改变现有服务。默认完整研究模块，可逐层展开和重新封装。降低操作门槛，同时始终展示数据、环境、修订和执行状态。

## 实施边界

本地项目以选定文件夹和独立.quantlab目录运行，项目间独立数据与任务。打开其他项目可启动另一实例，原项目任务继续，不热切换正在运行的数据库。账号版认证、角色及协作默认保持原行为。本地受信Python仍是可执行代码，目录授权不是对抗恶意代码的沙箱。

文件无限制指不设置统一上传字节上限，不承诺无限内存。预览有显式limit、total/是否已扫描完整信息；大型CSV/Parquet按块或分区读。模型训练和图表继续明确各自资源约束。外部引用变化会阻止把新数据当成旧输入，迁移时支持重新定位；严谨复现应复制/冻结输入。

依赖安装针对明确解释器，由操作按钮发起；可在线从标准包索引安装，或使用本地wheel目录。基础桌面不强制打包全部GPU依赖。安装、探测、运行都有状态和失败原因，不能把安装脚本存在等同于已安装成功。

## 实施顺序与验证

先修D1—D7与结构化契约；随后完成右侧会话编排和本地项目/权限/数据入口；接入环境选择、任务与缓存/迁移/模块库；完成桌面封装、安装器及运行验收。回归原有账号版工具和研究模块，使用隔离项目与构造数据验证，不改用户已有研究记录。对确受外部构建环境限制的交付，记录具体未通过项和可复现日志，不标完成。

桌面壳和打包依据官方文档：[pywebview API](https://pywebview.flowrl.com/api/)、[Inno Setup文档](https://jrsoftware.org/ishelp/)（独立CPython目录 + 原生启动器 + 每用户安装器）。
