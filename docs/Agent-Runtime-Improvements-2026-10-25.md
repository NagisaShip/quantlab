# Runtime 修复与性能复核（2026-10-25）

本轮承接《Agent-Runtime-Benchmark-2026-10-25.md》的问题清单，优先处理通知包装层的重复交付与假完成，并优化持久化开销。没有改版本号、推送或发布 Release，也没有调用真实模型或发送外部通知。

## 已修复

- 每日简报和维护评估使用持久业务身份：工作区、发起人、Agent、业务日期、通道及预览模式共同确定一个执行。首次输入与模型绑定冻结，新进程和并发调用复用原执行。
- 交付通知成为独立的持久工具步骤，具有稳定 `effect_id`。模型结果或用量未知时不发送模板冒充完成；通知已发送但确认或数据库事务失败时进入核对，不加入旧通知重试队列。
- 在外部调用前保存通知记录及定时包装任务的 Runtime 依赖。等待时包装任务为 PAUSED 并释放槽位，Runtime 保持唯一执行状态权威；核对后才唤醒包装任务。取消时保留未结算模型费用与未确认效果。
- 跨日期恢复按原执行保存的日期/周期、通道和预览模式继续，不按恢复当天创建新业务操作。原执行丢失或身份不符时拒绝继续。
- 通知恢复接口及界面允许核对费用、外部效果、继续与取消。管理员能确认事实，只有原发起人能继续使用其模型配置；外来步骤及其他成员访问被拒绝。记录投影按事件序号更新，旧等待快照不能覆盖已确认交付。
- 未绑定候选版本服务时不再向模型宣称可调用 `propose_candidate`，界面改为维护建议，避免无实际效果的成功表象。
- 通用 Agent 分开计算模型回合与工具步骤预算，一轮多个工具不会提前耗尽模型回合。通知确认后直接完成，不额外调用模型写确认语。
- SQLite 最多复用四个空闲连接，归还前回滚未结束事务、解除只读模式，显式关闭可释放资源。事务、外键、同步级别和逐次日志一致性审计保持原规则。fork 后须重建 Journal。

## 同机配对性能

固定本地模型：3 次模型请求、2 次工具调用；两组分别预热 2 次，正式各 30 次，随机交替顺序。两组使用同一当前 Agent，只替换 Journal 为 `0f5a3df` 中的实现或本轮实现。64 次全部通过，外部费用为零。

| Journal | 正式样本 | 中位耗时 | P95 |
| --- | ---: | ---: | ---: |
| 优化前 | 30 | 110.77 ms | 131.61 ms |
| 连接复用后 | 30 | 67.70 ms | 85.77 ms |

中位耗时减少约 38.9%，P95 减少约 34.8%。P95 使用排序后 `floor(0.95*(n-1))` 的样本值。此实验衡量本机 HTTP、序列化与持久化开销，不能推导真实服务商响应速度，也不是开源框架排名。独立的跨框架固定模型复跑 110 次全部通过，但因机器负载差异，不与上轮绝对耗时直接归因比较。

证据：`evaluations/runtime-2026-10-25/improvements/journal-paired.json`；复现命令见 `scripts/runtime_eval/README.md`。

## 验证与限制

新增回归覆盖跨实例复用、并发调用、模型结果未知、通知确认丢失、外部成功后事务失败、旧投影覆盖、恢复权限、账本幂等核对、包装任务等待及取消，以及连接池只读隔离、回滚、容量与关闭。浏览器检查覆盖等待时不显示已推送、确认前禁止继续、确认后显示交付结果；页面截图已人工查看。

- 根目录全量：1585 passed、10 skipped，730.38 秒。
- SQLite/PostgreSQL Runtime 及宿主专项：218 passed，107.72 秒。
- 最后补充的跨日期恢复、包装取消、权限与 API/Worker 回归：36 passed，37.25 秒；包含全量启动后新增的检查及最终包装层修改。
- Chromium 交互验收：7 passed，覆盖研究室恢复、Team、额度、产物与通知核对。
- Windows 前端构建、修改范围 Ruff 检查与格式检查通过。
- 两个独立 Python 进程处理同一业务键：模型 1 次、通知 1 次；模拟未知模型时包装 PAUSED、无通知；模拟调用未绑定候选工具时 FAILED、无假发布。证据 `evaluations/runtime-2026-10-25/improvements/scheduled-audit.json`。

上述检查有重叠，不能相加当作独立样本量。全量中的十项跳过仍然保留，未用放宽断言换取通过；第三方库的两项弃用警告保留。

## 仍需继续改进

本轮未宣称解决模型内容的所有质量问题。结构化输出 schema 与有界修复、数字单位和资料引用约束、Word 分页与 PPT 物理页数控制，以及 LibreOffice 临时目录兼容问题，仍按上轮报告保留。策略维护真实候选服务仍未绑定，当前只提供评估建议。真实模型质量需要在这些约束落地后用相同题集重新评估；本轮固定模型性能样本不作为质量提升证据。
